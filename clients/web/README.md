# 知络浏览器学习入口

浏览器学习入口为 `/app/`，与 Go API 同域。提供目标、学习区管理、研究、目标内导师交流与真实教学工作区；保存目标本身不会调用模型或创建教学会话。可从首页授权自动获取资料后开始学习，也可从目标详情明确选择已有会话，能力不足时明确受限。

## 加密离线学习（独立发布开关）

离线学习位于 `/app/offline`。操作者需显式设置 `WEB_OFFLINE_ENABLED=true`，同时
启用 Web、配置既有 `OFFLINE_SIGNER_KEY_ID/PRIVATE_KEY/ISSUED_AT/NOT_AFTER` 签发器及
持久保存的 `PRIVACY_OFFLINE_CHALLENGE_KEYS`（沿用版本号至少为 2 的原清除合同）。
缺少其中一项会拒绝启动该配置。生产使用同源 HTTPS，loopback HTTP 仅用于本机开发。
初始浏览器信任根来自已配对的同源连接，后续轮换逐级验证原签名链；不改变 CLI 的
配对、原签名包、同步及隐私合同。关闭该开关停止新下载，已保存数据仍可核对与清除。

从在线课堂点击“下载离线学习包”，明确选择学习区、目标和会话。首次保存需明确同意、
输入两次独立长口令（至少 12 字符）并获得浏览器持久存储许可。创建库本身不下载内容；
再点击明确下载按钮才签发并保存一项活动。服务端冻结原上下文，后来的目标、知识或
路线变化不会改写旧题。当前适配 v1 支持 objective/open 的无帮助文本作答；未知内容
只读，未知作答/授权协议禁止提交。原答题和同步不推进在线课堂，不离线调用模型、
搜索或评分，也不在本地生成正式 Evidence。

界面区分尚未保存的输入、已保存未同步、同步结果未知、服务端确认、拒绝、冲突及
待评估/复核。只有 strict IndexedDB 事务提交并回读成功才显示已保存。已保存答案
不可修改。重新联网且库已解锁时先查询所有结果未知的原操作，再同步允许的队列；
也可使用“核对原操作并同步”。网络在线不等于接纳，正式接收回执与 Evidence 状态
分别显示。下载响应丢失则使用“核对并恢复原下载”，保留原请求及签名。

浏览器普通登录仍为 12 小时。用户明确授权的离线专用 HttpOnly Cookie 只访问离线
合同，每次明确下载后最多有效 37 天；普通登录、查询和后台同步不续期。Cookie
丢失、到期或设备撤销后无法改用新设备提交旧包。请在界面显示的期限前联网同步；
同步身份不是解密密钥，口令不发送服务器，退出普通登录不会销毁离线库。

正文、包清单、原请求、答案、队列和回执使用 AES-256-GCM 认证加密。随机 DEK 由
独立口令经 PBKDF2-SHA256（60 万次，随机 128 位盐）派生的 KEK 包装；磁盘只保存
包装密钥及密文，解锁密钥仅在内存。刷新/关闭需重新解锁，15 分钟自动锁定，手动
锁定通知所有标签页。Web Locks 串行保存/同步，清除还等待其他解锁页面释放密钥。
WebCrypto 不是系统钥匙串或端到端加密；无法防御同源恶意脚本在解锁时读取内容。

目前发布验收范围为 Linux 桌面 Chromium（具体版本见验收记录）。其他浏览器、
原生移动浏览器尚未声明支持。必须同时支持 Ed25519/AES-GCM、IndexedDB strict
事务、持久存储许可、Web Locks、BroadcastChannel 与 Service Worker。隐私模式、
拒绝持久化或配额不足时拒绝保存。初始化至少需要 64 MiB 可用配额，明文快照上限
32 MiB，每库最多 10 万次写入；接近上限应先同步再明确清除。任何错误都不降级明文。
手机尺寸布局可使用多行输入，实际移动操作系统和软键盘仍需独立发布验收。

浏览器清理/逐出仍可能丢数据，持久化许可不是永久备份。部分丢失或密文损坏会停止
读写；若整站数据连标记一起被清理，只能明确提示“未发现离线库”，无法凭空判断
旧答案。口令或密钥丢失无法恢复；本版本提供丢失提示与确认销毁，不提供导出恢复
或跨设备接管，未同步答案不在服务器备份。重新创建空库不会恢复历史答案。

“清除全部本地离线数据”会具体提示未同步/待处置数量；库不可读时明确提示数量未知。
清除包含密封库、答案、队列、索引、包装密钥、内存密钥及本应用离线缓存，不删除
服务器已接纳事实。失败显示待完成，不宣称成功。真正断网设备无法即时远程擦除；
重新联网核对原设备 purge challenge，清除并核对后才提交正式 ack。页面挂起阻止
密钥释放时清除失败，需关闭相关标签页后重试。ack 响应丢失后刷新核对原设备、原代次
的已完成回执；无回执时仍显示待完成。服务端学情/隐私事实仍以原 owner
裁决为准，旧代次不得重新上传正文。清除不覆盖浏览器外用户副本、系统快照或取证残留。

Service Worker 只缓存本构建的白名单资产和固定离线页壳，注册发生在明确授权之后；
安装请求不携带身份，任何 API、登录响应、私人正文或外部 URL 都不会进入 Cache API。
安装时逐文件核对构建摘要，混合版本拒绝缓存。新壳随构建版本发布并等旧页退出后切换；
敏感数据始终在独立的版本化密封库内。

方案与验收记录见 [浏览器离线方案](../../docs/design/browser-offline-learning.md)和
[Issue #39 验收](../../docs/development/issue-39-acceptance.md)。

## 可选本地连接

服务器开关 `COMPANION_ENABLED` 默认关闭；学习 Cookie 和管理凭据均不提供本机 OS 权限。
设置页有独立“本地连接”说明。安装独立 companion 后，在具体导师对话内配对本机，
两端核对设备身份，再分别授权文件、原生 Shell 和模型外发。
文件写入先展示冻结预览，用户单独确认；任务面板提供真实状态、分页输出、stdin、停止及 PTY 控制。
模型只有在显式允许外发且设备在线时才获得转发工具；服务端没有 Shell 执行器。

切换/关闭对话、撤销或程序退出会按租约收尾；刷新或重启不自动恢复授权。
命令/输入响应未知时查询原回执，不重新执行。文件权限不限制 Shell，私人文件和终端回显
会经学习服务器传输，授权模型外发后按当前对话保存模式处理。
安装、卸载、风险和详细生命周期见 [companion 使用说明](../cli-go/README.md#可选本地-companion)。
当前仅取得 Linux 原生证据，Web 构建/浏览器与 macOS 原生验收缺口见
[Issue #38 验收记录](../../docs/development/issue-38-acceptance.md)，未通过前不视为发布完成。

## 本机开发

需要 Node.js 22.12+、Go（版本以 `server/go.mod` 为准）和独立 PostgreSQL。

```bash
make server-build
DATABASE_URL='postgres://用户:密码@127.0.0.1:5432/数据库?sslmode=disable' \
MIGRATE_ON_START=true WEB_UI_ENABLED=true WEB_UI_ALLOW_LOOPBACK_HTTP=true \
LISTEN_ADDR=127.0.0.1:8080 PUBLIC_BASE_URL=http://127.0.0.1:8080 \
./server/edu-agentd serve
```

通过同一 `DATABASE_URL` 运行 `./server/edu-agentd pairing-code create`，或使用既有本机管理页获取一次性配对码。在 `http://127.0.0.1:8080/app/` 输入配对码，设置浏览器名称后即可使用。保存目标不以模型、搜索或资料为前置。

`make web-build` 安装锁定依赖、检查类型、生成 Vite dist，并复制到 `server/internal/webassets/dist`。`cd clients/web && npm run dev` 监听前端源码并在每次构建后复制资源；重启 `go run ./cmd/edu-agentd` 后 Go 会嵌入最新资源。开发流量始终经过 Go 的同域 Cookie/CSRF 路径。没有跨域 Vite 开发服务器或代理身份。

若只检查 Go 代码且不启用 Web，可直接运行 Go 命令；启用 Web 但没有真实资产时服务启动失败。发行必须用 `make server-build` 或 `go build -tags web_release`，缺少入口或 assets 会在编译时失败。Dockerfile 也先构建真实前端再嵌入 Go。

发布检查入口为仓库根目录的 `make web-release-check`；完整自动化候选为
`TEST_DATABASE_URL=专用测试库 make web-release-candidate`，其中包含全局清除用例，
不可使用既有部署数据。候选串行运行 Chromium/Firefox/WebKit，每个测试文件独立重启
夹具。日常 `npm run test:browser` 仍只选 Chromium；设置 `WEB_RELEASE_MATRIX=1`
可用 `--project=firefox` 或 `--project=webkit` 定向诊断。需要按锁文件准备依赖和对应引擎，
脚本不自动安装。完整发布仍须通过[外部/人工门禁与 A01–A36](../../docs/development/issue-37-acceptance.md)。

## HTTPS 部署

设置 `WEB_UI_ENABLED=true`、`PUBLIC_BASE_URL=https://你的域名`，关闭 `WEB_UI_ALLOW_LOOPBACK_HTTP`。保持 Go 监听 loopback，使用 [Nginx 白名单示例](../../deploy/web/nginx.conf) 终结 TLS，只暴露 `/app` 与本次学习 API；`/admin`、`/internal`、`/mcp` 均不公开。不要把完整服务端口绑定到公网，也不要将旧管理代理信任配置用于公开入口。现有管理网络配置和独立管理凭据要求不变。

学习 Cookie 为 `__Host-edu_web`，Secure、HttpOnly、SameSite=Strict、Path=/、无 Domain。loopback HTTP 开发例外采用 `edu_web_dev`，必须单独启用。配置必须使用访问页面的精确 scheme/host/port，HTTP 层不根据转发头推断 Origin。学习 Cookie 与 Authorization 同时存在时拒绝；所有使用学习 Cookie 的非安全请求都校验 Origin 和 `X-CSRF-Token`。

浏览器会话固定有效 12 小时，存储于 PostgreSQL，可跨服务重启恢复。普通学习设备继承配对码已有的 `learning:read/write` 与 `knowledge:read`，新配对也保留原有 `memory:read`、`privacy:read`、`devices:read`，不会因此获得资料写入、审批或管理权限；每次请求读取实时权限、设备撤销、过期与隐私代次。旧设备不自动增权，缺少资料读取权限时需用新学习配对码重新配对。退出只删除当前会话。管理页与学习页同源时，携带学习 Cookie 的管理请求会被拒绝；使用独立浏览器上下文访问管理面，或先退出学习会话。

## 长期记忆、数据与设备

`/app/memory` 提供候选、已保存、纠正和交付状态。操作者通过本机
`edu-agentd pairing-code create --profile memory` 明确授予新设备
`memory:web`、`memory:read/write`、`privacy:read`、`devices:read/manage`，
以及普通学习所需的 `learning:read/write`、`knowledge:read`。旧身份不会自动升级；
收回 `memory:web` 后 Web 写记忆和撤销设备均失效。此档案不含 settings、资料审批、
配对管理或 admin 权限；隐私清除仍另需一次性本机授权。

候选展示具体正文、理由、类别、敏感性、稳定性、期限、版本和实际全局范围。
Web 新建及纠正必须另行明确批准，拒绝或取消不会创建正式记录。纠正须先读取
已交付原记录；审批按候选及原记录版本执行，过期或冲突需重新审阅。
批准产生正式记录和交付队列，不代表 Nocturne 已完成。删除及重放也使用原
memory 服务、版本和权限；等待、拒绝、未知和已验证状态分别显示。
导出经确认后仅下载全局正式记录当前页（最多 25 条），下一页须单独导出；
远端未配置/不可用时保留缺失状态，不虚构正文。导出不包含模型或搜索配置 Key，
但可能含敏感记忆正文，下载副本不受服务端清除控制。

Web 导师仅能通过 `request_memory` 申请具体长期偏好并暂停，用户在内嵌记忆面板
审批后点击“核对回执”继续；普通回复“好”、确认交流方向和保存聊天均不批准记忆。
今天、本次等临时要求仅用于本次。导师按原权限读取已批准且已交付的全局信息，
显示来源记录、版本和范围；正文实时读取，不另存到运行 checkpoint，发送前再核对
撤权、删除与版本。正式学习事实沿用当前目标/教学会话的原工具，Nocturne 不是
成绩册或 mastery 真值，不自动授权读取其他学习区私人正文。

`/app/settings/data` 明确区分临时聊天、删除聊天、归档目标、移除资料引用、逐条
删除长期记忆和全局隐私清除。全局清除需本机
`edu-agentd privacy-grant create --device <当前设备 UUID>` 签发短时一次性授权。
输入授权并二次确认后才调用原服务；不把本地清缓存当作服务器完成。地址在提交前
保留无正文的原操作和设备 ID；旧会话失效后重新配对，再打开该地址通过
`GET /v1/privacy/operations/{operationID}?device_id=...` 查询真实逐 owner 回执，
不要因丢响应重复发起。授权不进入 URL 或浏览器存储。

清除是全局、不可逆的旧代次屏障；运行、历史、checkpoint、来源、索引和记忆由
各自 owner 清理，失败或部分完成保持可见。最小审计及回执保留。外部提供商留存、
自行导出、WAL、宿主快照和非受管理备份不在物理擦除保证内；模型/搜索 Key
需另行在配置页清除及向提供商撤销。

`/app/settings/devices` 展示当前 Web 会话及已有权限下的设备列表；撤销须二次确认，
使该设备新请求和活动订阅的实时权限检查失效，不删除学习正文。所有危险对话框
默认聚焦取消；错误只显示固定说明及请求 ID。参见
[开发方案](../../docs/design/web-memory-privacy.md)和
[验收记录](../../docs/development/issue-34-acceptance.md)。

## 评估反馈与证据审批

课堂提交答案后可打开“查看原答案、接收回执与评估详情”；侧栏“评估与证据”按本区查看
全部记录、待评估及待复核。详情 URL 为 `/app/spaces/:spaceId/feedback/:attemptId`，
不依赖当前课堂焦点。接收、处理中、租约过期未知、建议待提交、失败及结算分开展示。
回执绑定原 operation/session/activity；旧版本题目、答案、标准和来源不随新内容更新。
迁移前未保存正文关联的答案明确显示“未知”，不猜测当前版本。

页面分开展示讲解、模型评分建议、原字符串匹配结果、追加的人工处置及有效 Evidence。
字符串匹配不是数学等价、代码执行或口语能力验证；模型置信度不是综合成绩。
帮助等级及证据不足原因保留。揭示答案不产生掌握证据；自述已会、阅读或继续不等于掌握。
来源不足不能直接复核接纳；低确定性、冲突与歧义按既有政策要求人工核对，覆盖仍需逐项
提供原答案和允许来源中的准确引文，由服务端校验 UTF-8 范围、摘要及完整标准。

普通浏览器身份只读评估。需要处置时，操作者在本机显式生成
`edu-agentd pairing-code create --profile assessment` 配对码，再用它配对新浏览器设备。
该档案只增加评估所需 `learning:approve` 和 `assessment:web`，不包含资料写入、知识审批、
设备管理或设置权限；旧 user/agent 身份不会增权。撤销审批 scope 或标记立即收回浏览器能力。
复核、覆盖、作废均要求原因与具体确认，同时校验会话版本和处置版本；历史纠错不切换
当前活动。网络错误先“核对原处置”，重试沿用原操作身份。刷新页面会丢失未保存的内存输入，
可重新按原答案查询正式历史。

同页消费已有真实“证据继承提案”，显示原 Evidence、知识/节点/文档版本及逐项目标映射，
可批准或拒绝。批准只建立待验证关系，不复制 Evidence、不自动跨目标迁移掌握度。
版本过期只可比较；服务端在审批事务再次校验基础和原证据，重试幂等。
既有继承协议仅支持默认学习区，其他区明确显示限制和入口，不暗中扩大旧协议。

新增查询 API 为 `GET /v1/learning/assessments`、`GET /v1/learning/assessments/:assessmentId`
和 `GET /v1/learning/attempts/:attemptId/feedback`；处置与继承仍使用原 owner API。
旧 CLI 严格 DTO 保持不变，复核原因在原 confirm API 中为兼容性可选，Web 必填。
迁移 `000030_assessment_feedback.sql` 只追加已校验的作答正文关联；新页面不导出或持久缓存
正文，查询复用知识/学习/教学隐私屏障，清除一并抹去关联，不能从历史页恢复已清除正文。
请同步更新 Nginx 白名单、Web 资产和服务端。方案与测试见
[评估设计](../../docs/design/assessment-feedback.md)及[验收记录](../../docs/development/issue-31-acceptance.md)。

## 动态进度、复习与跨目标继续

`/app/progress` 和侧栏“进度与复习”读取服务端正式聚合；首页先显示继续位置及到期复习，
目标详情使用同一组件和服务。可按全局、学习区、目标、目标状态筛选，按优先级/目标截止
时间或近期学习排序；复习按到期时间排序。总数与游标均来自服务端，不下载全库再筛选。
筛选可深链接，URL 仅含身份和筛选条件，不含私人正文。非法区/目标不会回退全局。

默认显示进行中目标及活跃区；显式选择暂停、完成、归档或全部状态可读取历史。隐藏不
删除复习、重设日期或开始任务。复习默认截止时间由服务端冻结并保存在游标中；手选截止
时间输入使用 UTC。投影、学习事实或区生命周期变化导致 `stale_cursor` 时明确回到第一页，
不拼接不同快照。网络/投影失败、重建/延迟、合法空结果与数据已清除分别说明；失败时可
展开原评估记录，全局回退默认区并提示选择其他区，不将失败显示为“没有复习”。

路线比例只代表明确修订内已确认的步骤，展示分子、分母、版本、更新时间和相对前版的
新增/移除项；不自动继承旧步骤完成。无路线时比例未知，无 Evidence 时掌握未知。
手动目标完成、路线步骤完成、模型反馈和正式 Evidence 分开解释。活跃时间标为事件间隔
估算，不是在线计时。原答案/证据链接复用 #31 的详情，不另设评分页面。

可继续入口绑定原区、目标、会话和活动。复习按 `task_id` 区分，不按节点 ID 跨目标合并。
原会话已完成或已离开原节点时，显示原因并保留原会话入口；在线来源可明确确认“新建复习
承载”。此操作沿用原目标/路线/知识 context，单独保存原任务、证据、答案身份，不迁移旧
会话或复制 Evidence。课堂再明确生成“本任务复习活动”并作答，新题和新答案各有新身份，
沿用既有调度算法。离线来源没有在线反馈身份时仍走原离线 API/CLI，不伪造在线答案入口。
同一承载创建丢响应后核对正式列表；同标签页重试复用原操作身份，其他标签页重复创建由
服务端拒绝。旧承载完成后只能由用户再次明确创建，历史关系保留。

API 沿用 `GET /v1/learning/progress`、`GET /v1/learning/reviews`；新增可选
`POST /v1/tutoring/sessions` 的 `review_source`（`task_id`、`evidence_id`、`attempt_id`）。
复习结果分别保留来源 `session_id` 和用户新建的 `carrier_session_id`；在线来源附带
`attempt_id`，可由 `GET /v1/learning/attempts/:attemptId/feedback` 读取原作答和结果。
CLI 的 `edu-agent progress --global --json`、`edu-agent reviews --global --json` 读取同一结果；
`edu-agent assessment show --session 会话ID` 可核对该会话当前评估，历史答案使用上述 API。
导师通过只读 `read_learning_progress` 获取其绑定目标的同一正式聚合，不能自行换区/目标。

迁移 `000031_review_sessions.sql` 只保存来源身份关系，隐私清除一并移除并验证无残留。
进度读模型版本升级为 2，启动时沿用既有重放租约重建，不改 Evidence、旧活动或复习间隔。
旧读模型未就绪返回 `projection_unavailable`，不伪造新字段。空范围的 `data_cleared`
根据权威清除墓碑判断，暂停或归档导致的空列表不是清除。Web 不增加持久正文缓存。
设计与验收状态见[进度设计](../../docs/design/web-learning-progress.md)及
[Issue #32 验收记录](../../docs/development/issue-32-acceptance.md)。

## NoteSync 来源同步

从“知识与参考”打开“同步”，或在任务中心选择“NoteSync 同步审阅”。入口为
`/app/spaces/:spaceId/notesync?collection=:collectionId`，审阅详情追加 `/:reviewId`。
页面显示真实连接版本、配置来源、固定学习区/集合、笔记库及管理前缀；任务中心保留
`open / resolved / closed` 原审阅状态。“已解决”仅表示本地审阅提交，远端发布需重新预览
核对，不能当作通用研究任务成功。

只有既有默认学习区与默认集合映射可用。研究集合、其他区、未映射集合和解除引用来源
均不能因为当前选择而继承同步权限。归档不允许新预览/解决；解除引用、归档、断开连接
及本地隐私清除均不表示远端副本、历史和备份已经删除。

普通学习身份可以读取与预览。正式解决还需要现有 `import` 或 `references` 配对档案
授予的 `knowledge:write` 与 `knowledge:approve`；仅 `research:adopt` 不足以审批同步。
Key 不回显，学习会话不能管理连接；操作者使用独立浏览器上下文，通过服务器本机
`/admin/` 或 SSH 转发管理入口修改连接，保存后重启生效，勿公开管理端。

操作顺序：

1. 生成同步预览；留空路径时逐页扫描，指定完整管理路径可单独核对。预览只读远端并
   保存审阅差异，不发布。部分扫描、前缀外结果和空页均不代表全库同步完成。
2. 打开审阅，核对发布基线、本地和远端完整正文、差异、路径、身份与版本。手机以
   “发布基线 / 本地正文 / 远端正文”切换面板；裁剪差异不能替代完整正文核对。
3. 采用远端或合并前，先“预览实际影响与身份”，复用知识导入计划、影响及身份审阅。
   身份冲突须逐项决定并重新预览。正式确认才使用原 NoteSync 解决服务。
4. 保留本地表示拒绝远端变化并排队回发本地正文，可能覆盖已核对的远端版本，不能
   当作无副作用的“关闭”。原合同没有独立“忽略/删除远端”动作，也不支持任意多 vault 映射。
5. 版本变化时旧审阅失效，保留原差异并重新预览。响应丢失时只读核对原操作；操作 ID
   保存在详情 URL，刷新仍可核对。404 仅表示尚无可读收据，不能证明未执行；不自动重放。

采用/合并沿用原知识导入和修订/发布事务。旧课堂与证据继续引用原版本，未来参考与教学
调整请进入“正式知识维护、参考资料及后续引用调整”，使用已有 #30/#26 变更合同；
同步本身不迁移教学上下文、不复制学习证据。正文和合并草稿只在内存，离页不保留草稿；
失去映射、引用、身份或隐私代次后不能通过历史页面恢复正文。

Fast Note Sync 3.6.1 仍不提供原子 CAS，上游并发窗口没有被 Web 改变。真实远端 smoke
与本地 fixture 验收分别记录，详见 [Issue #35 验收记录](../../docs/development/issue-35-acceptance.md)。

## 动态知识结构与维护

`/app/spaces/:spaceId/knowledge` 的“动态知识结构”按当前授权范围分页。局部图与下方
列表共用同一页数据，列表可完成键盘操作；裁剪提示不代表没有其他关系。同名概念按独立
身份保存，选择明确身份后才能提议合并或拆分。普通学习身份可读，具有 `knowledge:write`
的身份可提出候选，批准/拒绝和补偿还要求 `knowledge:approve`；可使用明确授权的
`references` 配对档案，旧身份不会增权。

新增或修订节点时，分别填写含义、来源状态、真实章节片段、具体主张、条件和待补充缺口。
服务器核对出处属于本区已关联集合且片段存在于该章节。来源状态与学习状态独立：有出处、
AI 建议或已纳入都不等于掌握。新概念修订不继承旧评估；“有证据”仅指确切修订上下文和
明确章节已有正式证据。详情提供相关目标、研究与参考角色入口，排除参考沿用原参考政策。

维护记录显示前后版本、身份映射和目标/context/活动/内容/证据影响。批准追加修订，
并发修订或新依赖使旧提案过期。响应丢失时核对原提案，不创建第二个操作。补偿从当前
基础建立新提案，不删除已发生学习。课堂“接入已审阅知识维护”通过 #26 的教学变更
服务生成候选，默认等本题处理后接入；当前题、答案、正文版本和草稿保留。概念维护不会
扩大冻结来源范围，新增出处须先在参考管理中正式采用。

“文档与章节维护”完整调用已有提案、审阅和回滚服务，保留原身份 receipt 与自动应用
政策。旧文档维护仍明确映射默认区/默认集合，其他区使用概念维护与已有参考管理，
不通过图接口修改来源原文。候选快照是完整集合，遗漏文档表示移除，请核对后提交。

迁移 `000029_knowledge_structure.sql` 追加结构字段、概念版本头、分页版本和提案/操作表；
不改既有概念、文档或评估身份，不需要新数据库扩展。已有修订成为首批可查询节点。
隐私清除删除新增 payload、关系及回执，旧概念/图/提案无法恢复正文；前端沿用身份隔离的
内存草稿和缓存清理，不增加本地持久存储。

设计与验收标准见[动态知识结构](../../docs/design/dynamic-knowledge.md)。独立数据库的
浏览器场景为 `npm run test:browser -- knowledge-structure.spec.ts`，需先构建生产 Web 资产与 Go 二进制。

## 可恢复导入与任务中心

全局“任务中心”位于 `/app/runs`。按学习区、类型及运行原始状态筛选；导入再选择资料集合。
运行和导入分别保留原 owner 的分页和状态，没有合并成功率。详情链接绑定原运行/任务，
刷新会先查询原状态；关闭详情仅停止观察，取消和继续均调用原业务命令。

导入使用已有 `import-jobs`。操作者可用 `edu-agentd pairing-code create --profile import`
生成具有资料写入及审批权限的配对码；该档案使用显式 `imports:web` 标记，收回标记后
浏览器不能继续写入或审批。它沿用现有 `knowledge:approve` 权限，包含资料集合变更，
不包含设备管理、教学审批或设置权限。已有浏览器身份不会自动增权。选择文件或目录后核对
完整清单，再创建一个任务自动逐文件传输。支持 UTF-8 Markdown 和纯文本；每文件 4 MiB、
每请求 16 MiB、每任务 1000 文件/128 MiB 的预算保持不变。纯文本保留原始摘要与可逆正文。

上传与解析不代表正式发布。先预览完整剩余计划，按批次审阅文档/章节身份和差异，再明确
确认计划版本，选择“继续一批”或“逐批继续”。跨批不保证全部成功或全部回滚。网络错误
会停止后续请求，先“核对原操作”；不会自动重新创建任务或重新上传全部来源。取消只阻止
后续发布，已经正式发布的文档和版本继续保留。

刷新、退出或丢失 File 权限后，从原设备的任务列表找到任务；未上传文件仍需重新选择。
补传前核对完整原清单的路径、字节数和 SHA-256，包括已上传项。来源变化需恢复原文件，
或建立新清单重新审阅。服务器暂存丢失可补传相同来源；集合基线变化会撤销旧批准；已过期
任务不可续传。归档区可查询和取消，不能继续发布。未提供跨设备接管。

正文、File、身份决定及扫描结果仅在本页内存中，不新增 localStorage、IndexedDB 或凭据
恢复缓存。任务 ID、学习区及集合 ID 在详情 URL 中，可能进入浏览器历史；它们不是授权凭据。
隐私清除与旧任务墓碑仍由原 owner 处理，不会凭 URL 复活旧导入。服务端暂存的配额、24 小时
到期及完成/取消清理沿用[导入任务设计](../../docs/design/import-jobs.md)。HTTPS 部署须使用
更新的 `deploy/web/nginx.conf`，导入路径允许 16 MiB 请求，其余业务仍由服务端各自预算约束。

开发方案和验收范围见[任务中心设计](../../docs/design/web-task-center.md)。浏览器断线验收：
`TEST_DATABASE_URL=独立测试库 npm run test:browser -- tasks.spec.ts`，必须先构建最新 Web 与
`server/edu-agentd`。不配置数据库或未运行浏览器测试不算验收通过。
每次启动验收服务会生成新的临时正文密钥，应使用新的空测试库；不要复用含旧密钥加密正文的数据库。
统一任务中心的原运行与内容导航验收可配置 `WEB_MENTOR_FIXTURE=1 WEB_WORKSPACE_FIXTURE=1`，
运行 `mentor.spec.ts` 和 `workspace.spec.ts` 中的选段模型加工用例；具体命令及结果见验收记录。

## 状态与隐私

已保存目标是服务端事实；选择属于每个标签页 URL；在线页面未提交正文和幂等重试身份只在标签页内存。刷新前提示会丢失草稿，退出或身份失效清除查询缓存和草稿。localStorage 仅保存主题和不含正文的离线库存在标记；没有明文答案、Token 或 Key。

新迁移 `000020_web_identity.sql` 只追加会话表，保存 Cookie 摘要、关联设备 token、代次和到期时间。长期设备 Token 不返回脚本，也不保存在 Web 会话表中。identity 隐私 owner 删除全部新增会话，并将残留会话数纳入校验。

查询与回调固定绑定 origin、设备 principal、隐私代次、空间和目标；历史查询带目标修订版本。业务请求先确认当前浏览器身份，并发送 principal/代次头防止检查与发送之间的身份切换。旧身份失败回调不会清除新身份。版本冲突保留输入，用户可读取最新版本后核对再保存；相同载荷重试复用 operation_id，修改载荷生成新操作身份。

## 版本化教学工作区

课堂中的导师可调用正式教学变更服务。“路径与教学变更”显示依据、旧新差异、影响和生效时点；
默认同目标调整在本题处理后接入，谨慎模式先预览。目标范围与完成标准始终需要具体确认。
明确立即切换会保留原题和按活动隔离的内存草稿，可返回原现场；补偿撤回生成新版本而不删除答案或证据。
该能力使用独立 `X-Learning-Change-Version: 1` 协议，需配置既有正文加密密钥；
新协议与旧教学 DTO 分离。详见 [教学变更设计](../../docs/design/adaptive-learning-changes.md)。

在目标详情的“继续学习”选择旧会话，或明确新建教学会话。地址为 `/app/spaces/:spaceId/learn/:sessionId`；始终读取 URL 中的原会话，不使用全局 current。来源栏显示真实路线范围和活动冻结的正规资料，不虚构掌握度。阅读活动无需正式答案；文本/单选答案走独立控件，Ctrl+Enter 或按钮提交。聊天使用 Enter/Shift+Enter，IME 组合态不会发送；可请求提示、分步引导和答案讲解，再返回原学习焦点。帮助等级按实际获得的帮助提交，刷新后需重新确认。

版本正文页面 `/app/content/:artifactId?space=:spaceId&version=:version` 支持独立阅读与内容加工，正式作答仍返回原教学会话；`/content/:artifactId` 是同源短链接入口。链接只含身份和版本，可用 `#block-:blockId` 定位稳定内容块。旧正规 Activity 确定性适配为首个正式版本，不改变旧 ID、事件或 rubric。内容版本只能追加，主学习页读取当前正式版，历史页展示最近 100 个版本，任意旧版仍可按版本号读取。新协议通过 capabilities 和 `X-Learning-Content-Version: 1` 协商；旧 CLI 继续使用原有严格 DTO 和字符串答案。

正文支持 Markdown、代码、公式、表格、引用、提示、题目、输入说明和组合块；不要求固定课序。Markdown 不执行 HTML，不自动加载图片，只允许用户明确打开 HTTPS 外链。公式禁可信宏/网络资源并限制长度、展开和尺寸；代码只展示，不运行。未知块显示文本回退，未知交互禁止正式提交。导师流式半成品仍是交流草稿；非法或不完整提案无法发行活动，内容 draft/failed 版本也不能取代正式版或提交答案。

旧题默认使用字符串文本答案。授权提交单选版本仅支持原题独立行的显式选项（如 `A. 2`、`B、3`）；完整选项集、标签与答案值必须一一匹配，允许重排但不能交换含义或隐藏选项。无法确定映射的旧题保留文本作答，不从 rubric 猜测或泄露答案。

正式答案丢响应后保留原操作 ID，核对原设备/区/会话的回执，不自动补发。活动草稿与待核对操作只在本标签页内存，按身份、区、会话、活动修订隔离；切页与主题切换保留，刷新不保证保留未保存答案。两标签页互不共享草稿，旧页面的迟到结果不会替换新页面状态。已确认的操作和正式内容由服务端恢复。

版本内容必须配置下述 `MENTOR_KEY_FILE`，新表 `000023_learning_content.sql` 使用 AES-256-GCM 保存所有版本正文、引用和生成依据，并绑定内容身份、权限主体和隐私代次。密钥缺失时保留原活动阅读，明确禁用版本化作答，不降级明文。正式内容不采用导师临时输出的七日 TTL，保留至全局学习隐私清除；清除通过 learning owner 同时删除版本、引用、操作摘要并验证无残留，既有导师流程清除运行增量与缓存。备份与密钥的恢复边界仍按下文处理。

已有真实会话可独立验收，不依赖研究。原会话后续活动生成需要正规资料和可用教学模型；空库的首项活动可由下述开学流程自动获得资料并准备，不假造来源。课堂反馈可展开原答案详情并通过正式审批路径复核。使用更新后的 Nginx 白名单，不能仅更新前端资源。

## 模型、搜索与预算设置

设置页通过 `/v1/settings` 保存和恢复服务端配置，`/v1/capabilities` 只读查询能力，不发外部请求。教学模型、Web 导师模型及搜索分别配置；导师仅在明确选择时复用教学配置，不覆盖独立配置。CLI 本机 Key 不读取、不上传、不迁移。研究与首项开学准备需要同时配置搜索和 Web 导师；原课堂后续生成使用教学模型，目标内交流使用 Web 导师。

操作者先设置独立绝对路径 `LEARNING_SETTINGS_FILE`，其直接父目录必须为 `0700`、文件为 `0600`，不能通过符号链接选择路径，也不能与 admin 设置共用文件。空路径只允许读取配置状态。Compose 将该文件放在服务器既有持久卷的独立 `learning-settings/` 目录。一个文件只供一个服务进程管理。

使用 `MODEL_ENDPOINT_ALLOWLIST` 的 JSON 数组精确授权模型 Base URL，例如 `["http://127.0.0.1:11434/v1","https://model.example/v1"]`。显式配置的旧 `MODEL_BASE_URL` 也只授权其自身。启用无鉴权本地模型时须明确选择“无鉴权端点”，不注入虚构 Key。禁止端点 URL 携带用户信息、查询参数或片段；不跟随重定向，也不使用环境代理转送凭据。搜索采用独立公共 HTTPS 网络策略，在 DNS 解析后检查实际 IP 并绑定拨号地址；模型允许列表不会授权内网搜索或网页抓取。

普通学习配对只读状态。需要修改或探测时，操作者通过本机 `edu-agentd pairing-code create --profile settings` 显式创建专门配对码，退出旧会话后用它配对新设备。新设备拥有 `settings:write` 和 `settings:probe`；旧设备与 user/agent 档案不升级。写入/探测必须使用学习 Cookie 并通过 Origin/CSRF 校验；Bearer、admin Cookie 不能替代它。通过既有管理入口撤销设备后，该权限立即失效。仅在服务端数据库显式收回某个 scope 时，也会在下一次请求立即生效。

教学配置与预算保存后显示“需重启服务”，现有教学执行继续使用启动时冻结的配置；重启后从新配置构造真正的模型适配器。配置保存和探测立即可用。新导师运行立即读取明确配置；运行中的配置指纹不匹配会停止后续调用，不隐式切换教学、CLI 或 admin 设置。旧环境教学配置在未被显式编辑之前仍由环境拥有；保存搜索或预算不将环境 Key 迁移进文件。文件中的显式教学配置优先于环境起点；恢复环境管理需先停止服务，由操作者在备份后移走完整设置文件并重启，这也重置其他服务端设置，应谨慎执行。

搜索实现 [Brave Web Search 官方接口](https://api-dashboard.search.brave.com/app/documentation/web-search/get-started)，默认地址为 `https://api.search.brave.com/res/v1/web/search`，Key 只放在 `X-Subscription-Token` 请求头。连接通过中立 `websearch.Adapter` 边界，后续可增加适配器。目标研究使用该适配边界及独立的安全网页抓取器。

“测试连接”必须逐次确认可能的外部请求与费用。模型发送固定公开 JSON 样本，原生 Schema 不支持时最多回退一次，共最多两次请求、每次最多 64 输出 Token；搜索仅查询公开词 `education` 并请求一条结果。整体最多等待 15 秒，响应大小有界。不发送私人目标、正文或成绩。返回已配置/禁用/缺配置/未探测/过期状态，以及鉴权失败、限流、超时、不可达、无效响应等分类和时间，不能用成功证明长期稳定。成功有效期 15 分钟；到期只显示过期，绝不自动重测。配置变化清除相应旧探测结果；并发修改期间的过时结果不会覆盖新配置。readiness 使用记录，不自动发模型请求；旧 `/v1/model/capabilities` 仍保留给具有旧 `model:probe` 权限的客户端，并保持原有显式调用语义。

预算使用整数并有服务端验证：研究请求默认 20（1–1000）、研究 Token 默认 100000（1024–10000000）、输出默认 2048（64–32768）、上下文默认 32768（4096–2000000）、无响应默认 60 秒（5–600）、并发默认 2（1–16）、存储默认 512 MiB（16–1048576）。输出须小于上下文且不超过研究 Token 预算。旧环境模型启动时使用其已配置的上下文和请求超时作为初值，仍需符合这些范围。当前教学为非流式请求；导师复用共享流客户端，按实际活动重置无响应计时。导师每次实际 HTTP 尝试（含兼容回退）都检查请求与 Token 预留额度，接受/继续时检查存储配额，承领时检查全局并发。提高工作进程并发需重启，降低上限立即约束新承领。研究复用这些服务端额度，不提供金额计费，也不限制固定教学轮数。未知提供商价格只显示请求用量和费用未核实。

外部搜索默认不允许私人目标、正文和成绩；设置中的策略不能代替任务授权。当前研究只发送用户确认的公开主题，即使设置允许私人查询也不会自动拼入私人字段。用户发起导师交流会将本次绑定目标与交流发送给所选模型端点；面板和设置页显示发送位置。导师交流不注册搜索工具，研究使用独立执行类型。

## 目标内导师运行

此节描述既有 run 协议和七日运行恢复合同。新 Web 对话管理使用下面的长期历史层；旧运行不会自动导入。

在目标详情明确发起交流后，即使关闭页面，Go worker 仍会执行。重新进入该目标恢复同一设备的当前会话/运行；SSE 只观察，不执行模型。需停止时使用“停止运行”，预算不足时可拒绝追加并停止。交互回应绑定 interaction 与运行版本，旧页面回应不能批准新候选。仅注册 `read_goal`、`ask_user`、`confirm_focus`；不提供 Shell、SQL、CLI、研究或改写旁路，也不会自动开学、修改目标或写掌握度。

默认临时模式：交流正文只在单个服务进程内存中，刷新/断线可恢复，跨进程或服务重启不可恢复；原操作回执仍持久。多副本部署的临时模式需要粘性路由，不能把临时正文可用性当作共享持久状态。明确勾选保存后，必要恢复正文保留至创建后的七日，使用 AES-256-GCM 加密写入 PostgreSQL。运行 checkpoint 最多 256 KiB，累计输出最多 64 KiB，事件 outbox 每运行最多 128 条且不含正文；大输出合并写入，不逐 Token 无限留存。配额按有界正文和事件预留，清除/到期释放正文配额，正式回执计入剩余配额。

保存模式需操作者设置 `MENTOR_KEY_FILE`：独立、规范绝对路径的原始 32 字节随机密钥文件，仅服务账户可读（例如 `0600`），不能是符号链接或与模型/admin 设置共用文件。密钥为空时只允许临时模式；配置了无效密钥则服务启动失败，不自动换钥匙或降级写明文。操作者应使用系统密码学随机源生成并独立安全备份，容器部署通过只读 secret/bind mount 单独挂载，不放入数据库卷、源码或静态资产。当前只有单一活动密钥；替换前应清除不再需要的保存正文，保留需恢复备份所用的旧密钥。丢失密钥无法恢复旧正文。

“清除本次正文”会停止运行、删除 checkpoint 和旧事件、释放临时缓存；全局学习隐私清除还覆盖载荷摘要及所有运行正文，通过既有 learning owner 的屏障与清理校验。旧代次和已撤销设备无法继续读取正文。备份/WAL、提供商留存、交换区和服务器内存取证不受单条清除即时擦除承诺覆盖；按既有受管理备份期限另行处理。密钥与数据库备份必须分别保护；服务进程或 root 仍能解密数据。

租约过期且调用已发出时不自动重放，区分结果未知与费用未知；只恢复已提交 checkpoint。目标/学习区暂停或归档、权限撤销、代次变化、目标修订和配置变化都会阻止下一次付费调用与失效结果提交。停机可能留下部分回答，真实结果以恢复快照为准，不保证外部提供商恰好调用一次。

代理需采用更新后的 Nginx 白名单：事件流关闭缓冲/缓存，读取超时 75 秒。`MENTOR_STREAM_HEARTBEAT` 默认 `10s`（1–60 秒），`MENTOR_STREAM_WRITE_TIMEOUT` 默认 `5s`（1–30 秒）；慢客户端写超时释放持有的短读事务。每设备最多四个订阅，同一页面的面板共享连接；最后一个观察者离开即释放浏览器缓存。事件先取一致 watermark 快照再订阅，游标过期返回 `resync_required`。

隔离测试数据库上可运行 `WEB_MENTOR_FIXTURE=1 TEST_DATABASE_URL=... npm run test:browser -- mentor.spec.ts`。它只启动本地 HTTP 模型夹具，不属于真实提供商 smoke。实现和验收边界见 [运行设计](../../docs/design/mentor-runtime.md)。

### 秘密生命周期与备份边界

API 只接受新 Key 或 `clear_key`，读取不回显旧值。浏览器仅在密码输入期间持有新值，提交即清空；失败重试须重新输入。Key 不进入查询缓存、草稿、storage、URL、构建资源、日志或错误正文。更换供应商、端点或鉴权方式会清除不匹配的旧凭据；同端点替换可用于轮换。导师复用时先关闭复用，才能编辑其独立凭据。

秘密文件是权限保护的服务端明文秘密边界，不是数据库字段，也不是加密保险箱；拥有服务器进程权限或 root 的操作者可读取。原子替换文件前写入并同步临时文件，文件格式带版本，API 配置 revision 用于拒绝并发覆盖。不要把目录放入源码、静态资产、公开备份或日志采集范围；备份应由操作者单独加密并限制读取权限。学习数据库备份不包含此文件，但服务器持久卷备份可能包含它。

轮换顺序：向提供商申请新 Key → 在相同端点替换 → 显式测试 → 重启教学服务 → 在提供商撤销旧 Key。清除只移除当前文件中的 Key，教学进程启动时冻结的旧 Key 需重启后释放；不会擦除旧备份、文件系统历史、交换区、提供商留存或 CLI Key。必须同时处理相应备份并在提供商侧撤销泄漏凭据。学习隐私清除删除学习数据与会话，不删除操作者拥有的服务器配置；配置需单独清除。恢复备份会恢复当时凭据及配置，应重新检查权限、有效期并显式测试。

不确定的请求继续显示原 runtime 的未知结果/费用状态。待交互超过运行期限不能回应。
网络丢失提交响应时可以核对原回执，重试也沿用原操作身份。

保存的聊天位于自托管 PostgreSQL，使用独立 `MENTOR_KEY_FILE` 做 AES-256-GCM
静态加密；服务端可以解密，不是端到端加密。标题和轮次独立认证用途、会话及隐私代次。
永久轮次保留至主动删除；运行 checkpoint 仍最多七日。历史按页读取，每设备最多
200 个未删除会话，并计入既有存储配额。达到配额或上下文上限会明确拒绝，不淘汰
旧历史、不悄悄截掉工具组、不降级明文；可另开对话继续。

临时模式不持久正文、自动标题或摘要，只保留无正文的绑定、运行状态和操作回执。
当前服务器进程仍存活时刷新可能恢复内存正文；重启、切到其他副本或到期后明确
显示“临时正文无法恢复”，不能承诺刷新总能恢复。临时会话不能改为永久会话。
已明确批准并执行的目标、内容和学习操作仍由各业务 owner 保存，临时不等于撤销。

provider/endpoint 变化后，默认仅查看历史。面板展示原目的地、新目的地以及将发送的

### 正文密钥轮换与备份

`MENTOR_KEY_FILE` 同时保护导师、正文版本和教学变更。不能只换文件或只重封装聊天表。
操作者先停止所有实例并等待至少 30 秒，分别保存数据库与对应旧密钥的受控备份，
准备独立的 32 字节新密钥（规范绝对路径、权限 `0600` 或更严格），然后执行：

```bash
MENTOR_KEY_FILE=/受保护目录/旧密钥 \
  ./server/edu-agentd mentor-key rotate --offline --new-key-file /受保护目录/新密钥
```

命令检查仍活动的服务心跳，获取排他表锁，在一个事务中重封装运行、标题、轮次、
正式内容版本和教学变更全部密文。任何认证失败或存储故障回滚，不输出明文、不自动
生成丢失密钥、不修改业务版本。提交成功后把部署的 `MENTOR_KEY_FILE` 改为新路径，
再启动服务并核对历史。命令不自动覆盖密钥文件；若进程在提交回执前中断，应保持
停机并分别用对应密钥核对数据库，不能盲目重复轮换。

新密钥不能读取旧数据库备份。备份和对应密钥须独立保管；删除当前会话、全局清除
或轮换都不等于擦除了操作者的旧备份、交换区或模型服务商副本。按既有隐私清除
回执处理备份保留及销毁；禁止把清除前的数据库和旧密钥直接恢复为对外服务，必须
先在隔离环境重施清除屏障并验证。密钥丢失、损坏或未来历史 schema 都失败关闭。
密钥轮换后，尚未实施的短期参考预览票据需重新预览。

真实服务浏览器场景：在独立空库先构建 Web/服务，然后运行
`WEB_MENTOR_FIXTURE=1 TEST_DATABASE_URL=... npm run test:browser -- mentor.spec.ts tutor-history.spec.ts`。
测试只使用本地 HTTP 模型 fixture，不证明真实提供商质量或留存策略。

## 目标研究与来源

从目标详情进入“研究相关知识”，填写去掉私人信息的公开主题并明确同意外发。服务端不会自动把目标正文、成绩或身份拼入查询。可选择补充、优先网站或限制网站；限制范围同时作用于查询、候选和每次网页跳转。运行显示候选、已读取、部分解析和已采纳的真实数量，预算包含搜索、网页 GET/跳转和模型请求。

普通学习身份可以研究并查看来源。需要采纳时，操作者先运行 `edu-agentd pairing-code create --profile research`，再用新码配对；旧设备不会自动升级。`research` 档案具有目标内研究采纳所需的 `knowledge:write` 和 `research:adopt`，不包含设置、审批或管理权限。用户可以逐条采纳，也可在开始时明确选择“研究并纳入本目标参考”。自动采纳仅限被真实片段引用的新来源，不能覆盖身份、共享或同步发布。

SourceViewer 显示真实文本片段、上下文、获取时间、版本、指纹和覆盖。HTML 为静态文本提取，PDF 尚不支持；页面不执行脚本、不携带登录凭据、不绕付费墙。模型当前只核对每个来源前三个片段，综合结论和自拟例子分别显示，不写入正式知识或掌握度。

临时运行正文只保留在进程；勾选保存后沿用七日加密恢复。正式采纳的正文由 knowledge 保存，来源修订只记录指向它的范围和定位；运行到期或清除后仍可显示获准历史副本。“清除研究运行”清除候选缓存和综合结果，不撤销已采纳资料；全局隐私清除会一起清理正式正文、索引和来源关系。未采纳来源没有历史副本时明确显示缺口。当前验证结果和未运行项见 [Issue #22 验收记录](../../docs/development/issue-22-acceptance.md)。
