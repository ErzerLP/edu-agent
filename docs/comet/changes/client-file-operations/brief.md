# Outcome

为现有交互式 Go CLI Agent 增加本地项目文件操作能力：模型可以在一个明确、固定且受工作区边界约束的目录内读取、定位并按所选授权模式修改文本文件；工具结果可被 Agent 后续推理使用，但不会被误标为服务端权威快照或自动进入长期记忆。

# Scope

- 目标客户端是仓库当前唯一的交互式客户端 `clients/cli-go`。
- 首版提供结构化 `list`、`read`、`search`、`write`、`edit` 工具，不以任意 shell 命令代替文件协议。
- `edu-agent agent` 支持可选 `--workspace PATH`；未提供时使用 Agent 启动目录。工作区在 Session 启动时解析并固定。
- 所有模型可见路径使用工作区相对路径，文件执行器强制阻止工作区越界。
- 只处理 UTF-8 文本文件；读取、目录发现、内容搜索和文本修改均使用有界结果。
- 用户可在逐次确认模式与 `yolo` 模式之间通过 Agent TUI 切换；每个 Session 默认逐次确认。读取、列目录和搜索无需确认；逐次确认模式下所有 `write`/`edit` 都需确认，`yolo` 模式下工作区内文件操作无需确认。
- 复用现有有界工具调用、取消、活动状态、结果投影和上下文压缩机制，并为本地工作区结果建立独立 authority/freshness 语义。
- 文件读取和修改必须在所有支持平台上执行真实的路径、链接、大小、并发修改和资源上限校验。

# Non-goals

- 不把 shell、终端、进程管理或网络访问作为本 change 的文件操作能力。
- 不提供删除、移动、复制或通用多文件 patch 工具。
- 不提供工作区外任意文件系统访问。
- 不处理二进制文件、图片编辑、字符集转换或大文件流式编辑。
- 不把本地文件升级为 Knowledge、Learning、Memory 或服务端 canonical 数据。
- 不实现跨进程文件锁、多人协同编辑或文件版本控制系统。

# Acceptance examples

- A1: 用户从项目目录启动 Agent，或通过 `--workspace PATH` 指定目录后，模型可以列出、搜索并分页读取工作区内的 UTF-8 文本文件；结果只显示规范化相对路径，并在达到行数、字节数或结果数上限时返回明确的截断原因和继续方式。
- A2: `../secret`、工作区外绝对路径、NUL/控制字符、符号链接或 Windows reparse/ADS 等越界路径不能读取或修改工作区外内容，返回稳定错误且不泄漏宿主绝对路径。
- A3: 文件工具结果以本地工作区快照进入当前 Session，绑定路径与内容版本信息，不被标记为服务端权威快照，不自动写入 Nocturne，也不绕过既有会话取消和回滚语义。
- A4: `edit` 的全部替换相对同一原始文件匹配；目标文本缺失、不唯一、修改区域重叠或文件已被外部改变时失败关闭，且原文件保持不变。
- A5: `write`/`edit` 成功时使用安全的临时文件和原子替换策略，保留已约定的换行、BOM 和权限语义；同一目标文件的并行修改按稳定顺序串行化。
- A6: 逐次确认模式下，需授权的文件修改在执行前显示有界内容预览或 diff、规范化相对路径和操作类型；用户拒绝后文件不变。`yolo` 模式下工作区内操作不弹确认，但仍受路径、链接、资源和并发冲突校验。
- A7: 用户可以在 UI 中看到有界的文件工具摘要、受影响相对路径、修改 diff、当前授权模式和稳定错误码；默认收起长正文，不显示模型隐藏推理或不必要的绝对路径。
- A8: 取消正在运行的文件读取、搜索或修改时，不继续执行剩余兄弟工具或下一次模型请求；取消或失败的未完成工具组不会污染后续模型历史。
- A9: 工作区内不使用额外 protected-path denylist；隐藏文件、`.git`、`.comet` 和类似路径按普通文件规则处理。启用文件能力时，客户端明确告知这些内容可能被读取并发送给当前模型 provider。

# Constraints and invariants

- 工作区边界由客户端执行器强制，不依赖 system prompt 自律。
- 文件内容属于不可信输入，不能扩大工具权限，也不能覆盖系统或用户指令。
- 本地文件内容可能被发送给当前配置的模型 provider；启用文件能力时必须向用户明确这一数据流。
- 不设置工作区内的特殊路径 denylist；所有工作区内文件使用相同访问规则，但仍执行二进制、大小、UTF-8、路径和链接校验。
- 只返回有界、可恢复的工具结果；正文、搜索结果和 diff 均有独立字节/条目上限。
- 只接受规范化的工作区相对路径；默认不跟随会逃出工作区的符号链接或 reparse point。
- 文件写入授权必须使用专用、类型安全的文件操作授权，不得把普通 `ask_user_question` 回答解释为文件写权限。
- `yolo` 只取消用户确认，不取消工作区约束、参数校验、原子写入、冲突检测、取消传播和结果截断。

# Decisions

- 客户端范围：基于仓库现状，首版只扩展现有交互式 Go CLI Agent。
- 工具集合：首版提供结构化 `list/read/search/write/edit`，不含删除、移动、复制、通用 patch 或 shell。
- 工作区来源：支持可选 `--workspace PATH`，默认使用 Agent 启动目录；每个 Session 启动时固定根目录。
- 授权模式：每个 Session 默认逐次确认，并可在 Agent TUI 内切换到或退出 `yolo`；只读工具无需确认，逐次确认模式下创建、覆盖和 edit 均需确认，`yolo` 在工作区内完全免确认。
- 拆分检测：保持单一 Native change。读取与修改共享工作区执行器、工具注册、Agent loop、结果 authority、上下文投影和 TUI 状态，拆成并行 child 会反复修改同一核心区域；Build 按“工作区与只读工具 → 写入与授权 → 集成收口”的串行垂直批次推进。
- 保护路径：工作区内不设置额外特殊路径保护，所有文件按统一规则处理；工作区越界仍强制拒绝。
- 工具形态：借鉴 Pi 的结构化文件工具与可恢复错误/截断语义，不照搬其“本机用户权限即边界”。
- 安全模型：借鉴 Codex 的显式工作区、沙箱与审批分层，不以 shell-first 作为首版默认能力。
- 数据语义：本地文件工具结果是当前 Session 的本地工作区证据，不是服务端权威数据或长期记忆。

# Open questions

- 无。

# Verification expectations

- 使用 fake workspace 覆盖工具定义、严格参数解析、模型 tool-call → 执行 → tool result → 后续模型回答的完整链路。
- 对 list/read/search/edit/write 分别运行具名测试和受影响 package 测试；文件工具未稳定前不运行全仓或重型门禁。
- Unix 覆盖最终/中间符号链接、TOCTOU 目录交换、并行修改和原子发布；Windows 覆盖 reparse point、junction、ADS、盘符与大小写语义。
- 覆盖 UTF-8、BOM、CRLF/LF、超大文件、二进制拒绝、结果截断、取消、外部修改冲突和错误脱敏。
- 覆盖文件结果 authority/freshness、上下文压缩投影、取消回滚、工具活动摘要、diff 展示和专用授权隔离。
- 稳定候选运行受影响 Go package 的测试、vet、error-level diagnostics、CLI build、定向 race 和 `git diff --check`；无需 PostgreSQL、Compose、OpenAPI 或服务端黑盒，除非实现意外触达对应边界。
