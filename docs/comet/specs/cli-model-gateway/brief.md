# Shape：CLI 经服务端模型网关调用模型

状态：Shape 待审阅（2026-10-19），未进入 Build。来源为 [#122](https://github.com/ErzerLP/edu-agent/issues/122)（已读取正文，无评论）及 2026-10-18 已确认方向；依赖 [model-usage](../model-usage/brief.md) 已有台账和设置。下文按末尾问题的建议默认值描述，审阅确认后才能标记 Ready。

## 结果

用户在网页设置一次模型，CLI 即可使用同一配置，并在用量页区分网页与 CLI、不同设备的消耗。文件读写、命令和 PTY 仍在本机运行；CLI 可以明确选择本地直连，使用本地模型或自己的密钥。两种模式都不再有累计请求次数或 Token 预算。

## 范围

- 新 CLI 默认选择“使用服务端模型”，经配对、权限和隐私告知后发送；旧用户先保留原配置，再明确选择是否切换。
- 服务端负责鉴权、协议转换、流式输出、取消与用量记录；CLI 继续使用 Chat Completions 协议。
- 网关调用进入现有用量页，可按来源和设备筛选，查看一轮对话的多次调用，并按本机会话归集。网页只展示用量，不展示 CLI 对话正文。
- 本地直连继续使用本机配置和钥匙串，不进入服务端用量统计。未配对时可使用本地模型和本机工具；需要服务端的学习功能仍须配对。
- 网页与 CLI 共用“每轮工具调用上限”，默认不限。离线沿用上次同步值，没有同步记录时不限；达到上限后说明进展，等待用户继续。
- 移除 CLI 学习工作台残留的预算输入、余额和“增加预算继续”文案；保留单次输出、上下文窗口、文件资源、权限和超时限制。

## 非目标

- 不共享 CLI 与网页的对话、文件内容、工具执行记录或本机会话恢复数据；不在服务端执行本机工具。
- 不开放任意模型代理，不由 CLI 指定上游地址、密钥或任意模型；不把服务端密钥发给 CLI。
- 不修改 `packages/agentcore` 的模型协议，不建设新的计费、充值、预算或供应商对账系统。
- 不补记历史本地直连用量，不保证中断后的回答可重放，不在故障后自动换用另一服务。
- 不扩展 Responses 的托管工具、多模态和服务器保存对话等能力；不重做离线学习同步。

## 关键决定

| 决定 | 建议行为 |
| --- | --- |
| 模型配置只取服务端 | 使用网页 AI 助手的有效配置；启用“共用教学模型”时跟随教学模型。CLI 展示模型及有效上限，但不自行选另一模型。 |
| 设备权限明确开启 | 新 CLI 配对档案包含模型使用权限；旧设备在网页设备管理中明确开启，原令牌继续有效，不自动扩权。撤销设备立即阻止新的调用和后续输出。 |
| 中断不自动重发 | 断线后停止这次请求，保留已经显示的内容并说明结果是否未知；用户决定是否重试或切换本地直连。 |
| 网页保留容量 | 每个设备同时最多一次模型调用，所有 CLI 合计最多使用总并发数减一；繁忙时立即提示稍后重试。总并发数为 1 时提示先调至至少 2 才能使用网关。 |
| 用量不等于正文 | 一轮用户对话归为一项用量任务，每次真实外发分别记账；重试和兼容回退如有新外发也计数。缺失用量显示未知。 |
| 本地内容经过服务端 | 首次开启时说明：“问题、相关对话和工具返回的本地内容会经过此服务端，再发送给网页设置的模型服务。服务端不保存这些正文，只记录用量和设备归属。”此承诺不替代上游供应商的数据政策。 |
| 升级保留选择 | 新安装默认网关；已有本地配置的升级用户首次进入时看到迁移选择，建议切换网关，尚未选择时仍使用原本地配置并明确提示。密钥不迁移到服务端。 |

完整可观察合同见 [spec](spec.md)，协议、迁移和批次见[设计](../../../design/cli-model-gateway.md)。

## 拆分与 Ready

保留一个 change，不新增 Supervisor 或 child，按 G-A／G-B／G-C 三个有界垂直批次串行推进。拆分评估已执行：鉴权、协议、台账、客户端配置和共享工具设置跨模块，但共同完成“CLI 使用服务端模型且用量可查”这一主要工作流；它们共享模型配置工厂、网关合同、迁移和 CLI 装配入口，不能按前后端或协议层独立发布并声称完成本结果。预算清理也不是另建预算子系统，而是移除旧入口并接入同一设置。

本 spec 有 29 条验收；每批交付可运行入口，不安排只有表或 transport 的批次。G-A 交付显式选择网关的 Chat Completions 全流程，G-B 补齐 Responses 和兼容行为，G-C 完成默认切换、旧用户迁移与工具上限。三批使用同一组相关 Go／数据库／CLI 场景证据，完整候选门禁留到 Candidate。

Build 前需用户确认下列产品选择，并核对当时 migration 序号和部署边界；数据 owner、公共接口与首批退出标准均已列入设计。本次只写文档，不运行测试、不改 OpenAPI 或 migration，不生成 verification。

## 端到端验收示例

- 用户配对并开启服务端模型，CLI 请求模型读取一个文件；文件在本机读取，相关结果经服务端发给模型，回答逐步显示。用量页显示此设备这一轮的两次模型调用，没有文件内容或回答正文。
- 网页选用 Responses 模型，CLI 无需改变协议即可收到文字、工具请求和可展示的推理增量；工具仍由本机既有授权流程执行。
- 模型正在回答时用户撤销设备；服务端停止转发并取消上游请求，CLI 停止这一轮。已经发出的调用仍入账，没有报告的 Token 显示未知。不能保证撤回已经到达模型服务或本机的内容。
- 服务端不可用时，CLI 提示重试或手动选择本地直连；用户明确切换后使用原钥匙串中的密钥。后续直连不写服务端用量；不会自动重做已执行的本机操作。
- 网页将每轮工具调用上限设为 3，CLI 执行三次工具后收回工具并说明进展；用户选择“继续”才重新计数。一次回答里多个工具请求分别计数，模型回答和进展说明不消耗工具次数。

## 仍需用户决定

| 编号 | 问题 | 建议默认值与理由 |
| --- | --- | --- |
| U1 | 老用户升级后，要直接改用服务端模型，还是先保留原设置，让用户选择？ | **先保留并提示选择，推荐切换服务端。**避免原来只在本机处理的内容未经知情就改经服务端；新安装仍默认服务端。 |
| U2 | 服务端暂时不能用时，要自动使用本机配置，还是让用户手动切换？ | **手动切换。**避免重复调用、改变内容发送对象或意外使用另一把付费密钥；已经完成的本机操作不重做。 |
| U3 | CLI 要直接跟随网页 AI 助手使用的模型，还是可以从多个模型中另选？ | **只跟随网页 AI 助手的有效模型。**配置一次即可使用，不引入第二套模型列表和权限；需要另一模型时可明确选择本地直连。 |
| U4 | 是否始终为网页保留一个同时运行的名额，即使这会让 CLI 暂时不能调用？ | **保留一个，繁忙时提示稍后重试。**保证单个设备无法占满网页容量；总并发数为 1 时须先调至至少 2。默认总并发数 2 无需调整。 |
