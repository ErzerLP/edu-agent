# Shape：CLI 经服务端模型网关调用模型

状态：Shape 已确认（2026-10-20），Ready，可进入 Build，尚未实施。依据 [#122](https://github.com/ErzerLP/edu-agent/issues/122) 及用户于 2026-10-20 确认的 U1–U4；依赖 [model-usage](../model-usage/brief.md) 已有台账和设置。

## 结果

用户在网页配置模型后，CLI 只通过服务端调用模型，可在已配置、已启用的教学模型和 AI 助手模型连接中选择，并在用量页区分网页与 CLI、不同设备及实际模型的消耗。文件读写、命令和 PTY 仍在本机运行。不设累计请求次数或 Token 预算。

## 范围

- 移除 CLI 本地模型配置、模型密钥存储和直连路径；配对并完成首次隐私告知后才能调用模型。未配对提示配对，服务端不可用提示重试。
- 服务端负责鉴权、Chat Completions／Responses 适配、流式输出、取消和用量记录；CLI 继续使用 Chat Completions 协议。
- CLI 可选择网页的 `teaching`／`mentor` 连接，排除 `search`；只显示名称和有效上限，不接收模型地址或密钥。选择按服务端和设备记住，不能指定任意模型。
- 用量页按来源、设备和实际模型筛选，可归集本机会话各轮及每轮的多次调用；不展示 CLI 对话正文。
- 网页与 CLI 共用“每轮工具调用上限”，默认不限。每轮及明确“继续”时读取当前值；无法读取就提示重试，不以离线缓存启动模型循环。达到上限后说明进展，等待用户继续。
- 移除学习工作台及其接口的累计预算输入、余额和增额操作；保留单次输出、上下文窗口、文件资源、权限和超时限制。
- 已有不依赖模型的离线学习、状态查看和本机会话删除等独立命令保持原行为；不新增离线模型或离线工具模式。

## 非目标

- 不共享 CLI 与网页的对话、文件内容、工具执行记录或本机会话恢复数据；不在服务端执行本机工具。
- 不开放任意模型代理，不向 CLI 下发上游地址或密钥。
- 不修改 `packages/agentcore` 的模型协议，也不因 CLI 停用某入口而删除共享核心代码。
- 不建设新的计费、充值、预算或供应商对账系统，不保证中断后的回答可重放。
- 不扩展 Responses 的托管工具、多模态或服务器保存对话能力；不重做离线学习同步。

## 关键决定

| 决定 | 已确认行为 |
| --- | --- |
| U1：直接替换 | 项目尚未上线，直接替换配置、行为与接口，不承担版本兼容。 |
| U2：仅网关 | 所有 CLI 模型请求，包括上下文整理、自动标题和连接测试，都经服务端；不可用时停止模型调用并提示配对或重试。 |
| U3：可选连接 | 选择已配置、已启用的 teaching／mentor，按 target 发请求。所选连接失效时停止并提示重新选择；模型或发送目的地改变须先说明并确认，不自动换用另一连接。 |
| U4：并发默认 10 | 总并发范围 1–16，默认 10；给网页预留 1 个名额，每设备同时最多 1 个请求，默认所有 CLI 合计最多 9 个。繁忙立即提示稍后重试；设为 1 时提示先调至至少 2。 |
| 配对与撤销 | 新 CLI 配对 profile 直接包含模型使用权限；撤销设备立即阻止新的调用和后续输出，并取消上游请求。 |
| 中断不自动重发 | 保留已显示内容，说明未完成或结果未知；由用户决定重试，不自动重做本机操作。 |
| 用量不等于正文 | 一轮对话对应一项用量任务，每次真实外发分别记账，按实际模型记录；缺失用量显示未知。 |
| 首次隐私告知 | “问题、相关对话和工具返回的本地内容会经过此服务端，再发送给你选择的模型服务。服务端不保存这些正文，只记录用量和设备归属。”确认前不外发；切换另一服务端须重新告知。此承诺不替代上游供应商的数据政策。 |

完整可观察合同见 [spec](spec.md)，协议、文件边界与批次见[设计](../../../design/cli-model-gateway.md)。

## 拆分与 Ready

保留一个 change，27 条验收，按两个垂直批次串行推进。鉴权、协议适配、配置选择、台账和 CLI 装配共同完成同一模型请求链，拆为独立 child 会共享公共接口并留下不可运行入口。

- **G-A：仅网关的完整模型调用链。**合并原 G-A／G-B，同时交付 Chat Completions 和 Responses、模型选择、鉴权、用量、并发与直连移除。演示站使用 Responses，不能先移除直连、后补协议支持。
- **G-B：共享工具上限与预算残留清理。**承接原 G-C 的剩余工作，完成实际工具计数、继续行为及无累计预算的交互和接口。

U1–U4 已决定，无阻塞问题；数据 owner、公共接口、数据库变更、文件边界及首批退出标准已明确，满足 Ready。工作区为 `docs/shape-122`，本次仅修改这三个文档；Build 开始时核对当时的数据库 migration 序号，测试与 Candidate 验证留待实现后进行。

## 端到端验收示例

- 配对后选择教学模型并确认告知，CLI 请求读取文件；文件在本机读取，相关结果经服务端发送，回答逐步显示。用量页显示该设备这一轮的两次模型调用和实际模型，没有文件内容或回答正文。
- 选择 Responses 连接后，CLI 无需改变协议即可收到文字、工具请求和可展示的推理增量；工具仍按本机授权执行。所选连接被禁用时提示重新选择，不转用另一模型。
- 模型正在回答时撤销设备，后续输出停止，上游请求取消；已发生消耗仍入账，没有报告的 Token 显示未知。
- 未配对时提示配对；服务端不可用时提示稍后重试，不发模型请求。已有离线学习包仍可按原流程作答并等待同步。
- 网页将每轮工具调用上限设为 3，CLI 执行三次工具后收回工具并说明进展；用户选择“继续”才重新计数。一次回答中的多个工具请求分别计数，模型回答和进展说明不消耗工具次数。
