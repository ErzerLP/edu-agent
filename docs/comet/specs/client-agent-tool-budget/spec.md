# 客户端 Agent 工具预算完整规格

## 用户能力

Go 客户端的中文设置页和等价 `edu-agent model set --max-tool-rounds N` 命令允许用户配置单次 Agent 用户输入可进行的最大模型工具轮数。该值属于本地非敏感模型设置，保存到 `os.UserConfigDir()/edu-agent/config.json` 的 `agent.max_tool_rounds`，不进入服务端、模型凭据、设备凭据或 Agent Session 密文。

默认值保持 8。合法值下界为 1，上界为 60。值 60 必须能够从设置页和命令入口成功保存，并被新启动或恢复的 Agent Loop 接受。0、负数和大于 60 的值必须在保存前失败，保留上一次有效配置，并通过稳定 `invalid_configuration` 类别和明确范围提示告知用户。

设置页继续只负责收集输入并生成等价命令，配置规范化、校验和原子持久化由既有命令与配置层统一完成。设置页字段标签或帮助文本必须显示 `1–60` 范围，CLI flag 帮助与错误建议不得宣称不同边界。

## 运行时语义

一次用户输入开始时，Agent Loop 从已冻结的 Session 配置取得 `MaxToolRounds` 并初始化本 turn 的有限模型轮次预算。每次向模型发起一个会延续当前 turn 的 completion 都消耗一轮；模型返回最终文本或预算耗尽时结束。达到预算时继续返回现有有界错误，不自动提高配置、不在后台继续请求模型。

每次模型响应仍最多包含 4 个工具调用。用户确认总工具调用预算随轮数扩展为 `MaxToolRounds × 4`：配置 60 时最多进行 60 个模型工具轮，并在整个用户 turn 内最多执行 240 个工具调用。达到任一预算即停止后续模型或工具执行并返回现有有界错误。

总预算始终为确定有限值。配置校验与运行时校验必须共享同一最大轮数常量，不能出现保存成功但 Session 构造失败，或两个层级接受范围不同的情况。

## 安全、隐私与兼容性

提高最大可配置轮数不改变以下边界：单响应工具调用数、工具参数单项与总大小、工具输出投影、上下文预算、模型与工具超时、取消、文件工作区隔离、写操作确认或 YOLO 模式、长期偏好确认、敏感信息清理和 provider 错误脱敏。

现有 1..16 配置继续有效，默认值保持 8，用户当前值不会自动迁移。配置失败不得改写已有合法配置。Agent Session 的自动加密保存、每会话密钥、checkpoint/record 格式、自动标题、provider 摘要边界和恢复选择器不因本能力变化；既有会话不迁移、不重加密且保持可恢复。

## 可观察验收

1. 隔离配置目录中的 `model set --max-tool-rounds 60` 成功并原子保存 60。
2. 中文设置页输入 60 生成等价命令并成功保存，页面显示合法范围。
3. `agentloop.New` 接受 60，配置层与运行时使用同一最大值定义。
4. 0、负数和 61 被拒绝，旧配置保持不变，错误提示包含 `1–60`。
5. 默认值 8 和现有 1..16 行为不变。
6. 单响应最多 4 次工具调用以及其他资源、权限、隐私和会话持久化边界保持不变。

## 验证策略

配置单元测试覆盖 1、16、60、0 和 61；命令测试覆盖 60 成功持久化和 61 失败不覆盖；Agent Loop 测试覆盖 60 构造成功以及 0/61 失败；设置页测试覆盖范围提示和 60 的命令映射。精确回归通过后运行受影响 Go package 的完整测试、vet、CLI build、error-level diagnostics 和 `git diff --check`。该能力不修改服务端、OpenAPI、PostgreSQL、Compose 或平台凭据实现，不需要对应重型矩阵。
