# 客户端 Agent 工具循环完整规格

## 用户能力

Go 客户端的 Agent Loop 默认不设置固定的模型工具轮数上限。中文设置页和等价的 `edu-agent model set --max-tool-rounds N` 命令继续保留兼容入口：`0` 表示不限制，任意正整数表示用户主动设置的本地保护值，客户端不再定义最大合法整数。该值属于本地非敏感模型设置，保存到 `os.UserConfigDir()/edu-agent/config.json` 的 `agent.max_tool_rounds`，不进入服务端、模型凭据、设备凭据或 Agent Session 密文。

新建配置和模型预设默认保存 `max_tool_rounds: 0`。既有正整数配置继续按用户保护值生效，不被静默删除；用户可将其设置为 `0` 切换到不限制模式。负数必须在保存前失败，保留上一次有效配置，并通过稳定 `invalid_configuration` 类别说明 `0` 的不限语义。

设置页继续只负责收集输入并生成等价命令，配置规范化、校验和原子持久化由既有命令与配置层统一完成。设置页、CLI 帮助和 `model show` 必须一致显示：`0` 为不限制，正整数为可选保护值，没有固定上界。

## 运行时语义

一次用户输入开始时，Agent Loop 从已冻结的 Session 配置取得 `MaxToolRounds`。值为 `0` 时，模型推理与工具执行循环不会因为固定轮数、单响应工具调用数量、单 turn 总工具调用数量或用户问询次数而终止；循环持续到以下任一可观察终态：

- 模型返回不含工具调用的最终助手文本；
- 工具要求用户回答问题、确认长期偏好或授权文件修改；
- 用户取消、Session 关闭或调用上下文终止；
- 模型或工具触发各自的超时、协议错误或安全失败；
- 当前上下文在既定压缩策略下无法继续形成合法请求；
- 正整数 `MaxToolRounds` 用户保护值被消耗完。

模型单次响应可以包含超过四个工具调用，整个用户 turn 也可以执行超过旧有 `MaxToolRounds × 4` 预算的工具调用。客户端保持工具调用 ID 唯一性、类型、名称和 JSON 参数校验，并按模型声明顺序记录结果。流式模型响应不再以固定工具调用数量拒绝合法的连续索引；响应体、SSE 事件和单个协议载荷仍受独立资源边界保护。

用户问询工具不再限制每个用户 turn 最多四次，但同一 turn 内重复 `question_id` 仍失败关闭，避免迟到回答或重复调用绑定到错误问题。

## Codex 对齐原则

工具循环采用 Codex 的核心终止模型：模型产生工具调用时执行并把结果加入上下文，然后继续推理；模型产生最终助手消息时结束。客户端必须以迭代续行调度长循环，不得为每个模型轮次持续累积 Go 调用栈。长循环依赖上下文预算、工具结果投影和自动压缩维持可继续性，而不是用任意轮数或调用次数提前截断。

此对齐不等于取消资源与授权边界。Codex 同样依赖上下文窗口、输出截断、取消、sandbox/approval 和 transport 限制；本客户端继续保留相应安全合同。

## 安全、隐私与兼容性

取消固定调用次数上限不改变以下边界：用户输入和模型文本大小、工具参数单项与单响应总大小、工具结果 live/history/recall 投影、模型响应体和 SSE 帧、上下文预算与压缩、模型与工具超时、取消、工作区隔离、写操作确认或 YOLO 模式、长期偏好确认、敏感信息清理以及 provider 错误脱敏。

单个工具可以通过分页、cursor、offset 或截断标记继续读取，不允许以“无限循环”为理由一次性返回无界数据。文件写入、长期偏好和其他副作用仍使用现有确认、幂等、取消与未知结果合同。

Agent Session 的自动加密保存、每会话密钥、checkpoint/record 格式、自动标题、provider 摘要边界和恢复选择器不因本能力变化；既有会话不迁移、不重加密且保持可恢复。

## 可观察验收

1. 新模型预设默认 `max_tool_rounds: 0`，`model show` 和中文设置页显示“不限制”。
2. `model set --max-tool-rounds 0` 成功；大于旧上限 60 的正整数同样成功；负数失败且不覆盖已有配置。
3. `agentloop.New` 接受 `MaxToolRounds: 0` 和任意正整数，拒绝负数。
4. 不限制模式可以完成超过 60 次模型推理的单个用户 turn，并最终返回助手文本。
5. 单个模型响应可以包含超过 4 个工具调用，单 turn 可以执行超过旧有总调用预算，所有调用结果仍按协议进入后续模型请求。
6. 流式响应可以组装超过旧有 32 个工具调用的连续调用组，不因固定数量上限失败。
7. 同一用户 turn 可以连续完成超过 4 次有效用户问询；重复 `question_id` 仍被拒绝。
8. 上下文、单个协议载荷、输出投影、超时、取消、工作区和写入授权边界保持有效。

## 验证策略

配置单元测试覆盖 `0`、旧合法值、远大于 60 的正整数和负数；命令测试覆盖不限模式、无固定上界及失败不覆盖；Agent Loop 测试覆盖超过旧 60 轮和单响应超过旧 4 次调用；流式 assembler 覆盖超过旧 32 次调用；交互控制测试覆盖第五次及后续用户问询。精确回归通过后运行 `agentlimits`、`config`、`modelclient`、`agentloop`、`command`、`dashboard` 和 `agentcontroller` 的受影响 package 测试、vet、CLI build、error-level diagnostics 与 `git diff --check`。该能力不修改服务端、OpenAPI、PostgreSQL、Compose 或平台凭据实现，不运行对应重型矩阵。
