# 客户端工作区安全归档

## 已确认结果与范围

用户可让交互式 CLI Agent 将不再需要的普通文件（包括二进制）或整个目录移入固定工作区的隐藏归档目录，而不能让 Agent 永久删除它们。本次仅交付安全归档，不新增通用 find/stat/mkdir/copy/move/delete、长文本写入、回收站清理或自动恢复。

本规格扩展 `client-file-operations`；归档的专用规则优先于该规格中首版五工具集合、无移动工具及无 protected-path denylist 的描述，其余既有行为不变。

## 工具与保存位置

- 新增结构化工具 `archive`，输入仅为工作区相对 `path`，不允许模型指定目的地、覆盖策略、递归删除或永久删除模式。
- 接受普通文件和目录（包括非空目录）；不把二进制正文发送给模型。源路径本身或解析链中的链接、junction/reparse point、设备及其他特殊目标必须拒绝。
- 目录作为整体移动，不逐项复制、删除或跟随内部链接。目录内部的链接随目录保留，但不会被解引用。目录归档不是整个子树的内容快照或跨进程协作锁。
- 目的地固定为 `.edu-agent-archive/<UTC时间>-<随机唯一ID>/<原相对路径>`。首次实际提交时建立需要的归档目录；仅准备预览或拒绝授权不建立目录。
- 每次归档使用独立目的地，绝不覆盖已有归档。归档结果显示源相对路径、归档相对路径、目标类型和实际结果。
- 不自动过期、清理或淘汰归档；不提供模型可调用的清理或恢复工具。用户在客户端之外自行恢复或删除归档，磁盘空间不足时报错。

## 保护与授权

- 工作区根 `.`、归档目录本身及其后代不可作为归档源。路径别名不得绕过归档保护。
- 所有模型文件工具不得向归档目录写入、编辑或重新归档；专用归档执行器只能新增一个未占用的归档目标。
- 只读 list/read 可用于查看归档；从普通工作区范围执行的 search 默认跳过归档树，显式指定归档范围时可以读取其 UTF-8 内容。归档不改变当前 provider 的数据流告知与只读授权规则。
- 默认逐次确认，展示源路径、目标归档路径、类型和“由用户手动清理”的提示。确认只授权冻结的归档候选，普通问询回答不能授权归档。
- YOLO 对 archive 与 write/edit 一样仅跳过逐次确认，不绕过工作区、归档保护、目标不覆盖、版本检查或取消控制。
- 无任何永久删除文件/目录的模型工具或归档 fallback。内部临时文件与会话存储管理沿用原合同，正常文本 write/edit 仍可修改内容；本能力不是备份或内容版本控制。

## 执行、安全和恢复

- Prepare 固定源入口身份、类型和可观察元数据版本以及随机目标，不跨越授权等待持有文件锁。
- Commit 重新校验入口身份与元数据，按同一工作区内的安全 no-replace rename 移动；跨文件系统或不支持安全原语时拒绝，绝不 copy+delete。
- 不承诺目录后代在准备与提交之间没有被外部程序修改；对观察到的源入口替换或元数据变化返回冲突。保留既有非协作跨进程最终校验窗口限制。
- 取消前未移动源入口则不得报告已归档；移动完成后晚到取消不得声称未修改。已创建归档容器但后续失败时明确报告容器副作用，不删除用户数据以“回滚”。不能确定最终状态时返回 outcome_unknown，并停止自动推进和重试。
- 归档移动的源/目标信息纳入当前 Session 的副作用记录。恢复时不自动重放归档；结果未知时提示用户检查源和归档目标。
- 原路径和目录后代的历史工作区内容，以及受影响的目录列表/搜索结果应标记过时，不能继续代表当前磁盘；保留历史证据且不改变服务端数据权威性。
- 现有会话格式须向后兼容，旧 write/edit 回执和恢复行为不被破坏。

## 验收

1. 普通文本和二进制文件归档后源路径消失，原始字节完整出现在返回的归档路径。
2. 非空目录作为整体归档，子目录、文件与内部链接保持；不访问内部链接目标。
3. 相同源路径多次归档生成不同目的地，旧归档不变；目的地冲突不覆盖。
4. 根、归档树、路径逃逸、源链接、归档根链接及平台别名攻击不能绕过边界。
5. write/edit 对归档路径拒绝；未暴露 delete/rm/永久删除参数，归档实现不存在 copy+delete 路径。
6. Prepare/拒绝无归档目录副作用；允许后才执行；YOLO 跳过确认但保留保护。
7. Prepare 后源入口变化、取消、跨设备失败与无法确定结果分别返回真实且稳定的状态。
8. 授权面板与活动详情展示源/目标；已归档后续答失败或 Esc 不遗忘归档事实。
9. 会话保存/恢复保持归档回执和失效状态，未知归档不重放；旧会话仍可恢复。
10. 全程不自动清理归档；用户手动移除归档目录后，后续归档可安全重新建立。

验证采用具名 workspace/securefile 回归、授权和恢复的窄集成测试；涉及的平台安全实现分别记录原生执行与交叉编译证据，不以未运行代替通过。
