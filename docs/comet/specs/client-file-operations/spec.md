# 客户端本地文件操作完整规格

当前文件工具还包含 [安全归档](../client-file-archive/spec.md)：文件或目录的删除意图只能移入 `.edu-agent-archive/`，由用户手动清理；该专用目录禁止普通写入、编辑或再次归档。下述五个文本工具的核心合同继续适用；六工具集合、归档保护及整体目录移动以安全归档规格为准，不提供永久删除或通用移动工具。

## 产品目标

交互式 Go CLI Agent 可以在用户选定的本地工作区中检查、定位和修改 UTF-8 文本文件。文件能力使用结构化工具、明确的工作区边界、有界结果和可见授权状态，使用户能够让 Agent 处理项目文件，同时保持路径越界、并发覆盖、取消、上下文权威性和远端模型数据流可解释。

该 capability 只扩展 `clients/cli-go` 的交互式 Agent。它不改变服务端 Knowledge、Learning、Memory、MCP 或 canonical Markdown 的数据所有权。

## 工作区与启动

`edu-agent agent` 接受可选的 `--workspace PATH`。未提供时，客户端使用 Agent 启动时的当前目录。Session 启动时将工作区解析、规范化并固定；后续进程当前目录变化不能改变该 Session 的文件边界。

工作区必须是客户端可访问的目录。模型工具只接受并返回工作区相对路径，不把宿主用户名或工作区绝对路径注入模型工具结果。绝对工具路径、父目录逃逸、NUL、控制字符、平台非法路径和规范化后位于工作区外的目标必须失败关闭。

除安全归档规格规定的 `.edu-agent-archive` 写保护外，工作区内不设置额外 protected-path denylist。隐藏文件、`.git`、`.comet`、`.env` 和其他工作区内路径使用与普通文件相同的读取和修改规则。客户端必须在启用文件能力时明确告知用户：被读取的工作区内容可能发送给当前配置的远端或本地模型 provider，且 `yolo` 模式不会为这些路径增加确认。

符号链接、junction 和 reparse point 可以作为目录条目展示，但首版文件工具不跟随它们读取、搜索或修改目标。Windows alternate data stream、设备路径、盘符逃逸和等价重解析路径必须拒绝。

## 工具集合

首版向模型提供五个职责独立的结构化工具：

- `list`：列出一个工作区目录的直接子项；
- `read`：按有界行范围读取一个 UTF-8 文本文件；
- `search`：在工作区文件内容中执行有界文本搜索；
- `write`：创建新 UTF-8 文本文件或完整替换现有文本文件；
- `edit`：对一个现有 UTF-8 文本文件执行一组局部文本替换。

首版不提供删除、移动、复制、任意多文件 patch、shell、进程执行或网络访问工具。未知工具、未知参数、非对象参数、尾随 JSON、超出边界的数值或字符串必须在执行前拒绝。

文件工具只在 Session 已成功建立工作区时暴露给模型。工作区初始化失败时，Agent 可以继续没有文件工具的普通对话，但必须向用户显示稳定的不可用原因，不能暴露一个必然越权或失效的工具面。

## 列目录

`list` 默认只列目标目录的直接子项，不递归展开整棵目录树。结果按跨平台稳定顺序排序，目录、普通文件和链接类型可区分，目录使用一致的显示标记，路径统一为工作区相对 slash 形式。

目录列表包含 dotfiles，不因 `.gitignore` 或文件名自动隐藏工作区内条目。无法安全检查的单个条目以有界错误或跳过计数表达，不能导致无限重试或泄漏宿主绝对路径。

列表结果受条目数和总字节数限制。达到上限时返回机器可读的截断状态、已返回数量和继续或收窄范围的建议，不静默丢弃。

## 读取文件

`read` 只读取 regular UTF-8 文本文件。二进制内容、无效 UTF-8、目录、链接、设备文件、超出单文件安全上限的文件和读取期间身份发生变化的文件返回稳定错误。

读取使用 1-based 行范围，允许模型通过后续 offset 继续。结果同时受最大行数和最大 UTF-8 字节数限制，先达到者生效；不能为了满足字节上限返回半个 UTF-8 字符，是否允许返回半行必须使用一致、可测试的规则。

读取结果包含规范化相对路径、返回行范围、内容是否完整、截断原因和下一 offset。达到限制时必须告诉模型如何继续，不能把未知剩余内容表述为已完整读取。

## 搜索内容

`search` 在工作区 regular UTF-8 文本文件中执行文字或正则搜索，并支持有界的路径范围、include/exclude 和大小写策略。默认行为必须确定，调用参数必须明确区分 literal 与 regex，非法或复杂度超限的正则在扫描前拒绝。

搜索不跟随链接，不读取二进制或超出扫描上限的文件。结果稳定排序，并至少包含相对路径、行号和有界预览。单行预览、匹配数量、扫描文件数、扫描总字节数和工具执行时间均有上限。

无匹配是成功的空结果，不是执行错误。达到结果或资源上限时返回截断原因和收窄查询的建议；取消时及时停止剩余扫描。

## 写入文件

`write` 可以创建新 UTF-8 文本文件，也可以完整替换现有 regular UTF-8 文本文件。创建时可以安全建立缺失的工作区内父目录；父目录、目标或解析链上出现链接、reparse point、非目录组件或工作区逃逸时拒绝。

所有写入都支持内容版本前置条件。覆盖现有文件时必须校验调用基于的 expected hash 或等价版本；版本不匹配返回 `content_changed`，不能盲目覆盖外部编辑。新建文件在目标已存在时必须按“现有文件”路径重新授权和校验，不能把竞态中的覆盖误报为新建成功。

发布使用同目录临时文件和安全原子替换；失败或取消不能留下半写目标。实现保留适用的权限、UTF-8 BOM 和主换行风格，或者在无法保留时返回明确行为，不能静默改变未承诺的文件属性。成功结果报告实际 UTF-8 字节数、内容版本和操作类型，不把 JavaScript/Go 字符长度误报为字节数。

## 局部编辑

`edit` 只处理已存在的 regular UTF-8 文本文件。一次调用可以包含多个替换；所有 `oldText` 都相对调用开始时的同一原始内容匹配，而不是依赖前一个替换产生的新文本。

每个 `oldText` 必须非空、精确且在原始内容中唯一出现。不同替换区域不得重叠或嵌套；相邻或同一区域的修改应由模型合并。任一替换找不到、出现多次、重叠、没有实际变化或版本前置条件失效时，整个调用不发布任何修改。

首版公开合同使用 exact match，不隐式使用 Unicode、引号、dash 或尾随空白 fuzzy fallback。错误结果应提供可恢复建议，例如扩大上下文以获得唯一匹配、合并重叠替换或重新读取最新文件。

编辑成功使用与 `write` 相同的安全发布、内容版本和同文件 mutation serialization 机制，返回有界 diff、标准 patch 摘要、首个变化行和新内容版本。预览与实际发布结果不一致时，以执行前重新校验后的最终 diff 为准。

## 授权模式

每个 Agent Session 启动时默认处于逐次确认模式。TUI 提供当前 Session 内的显式控制，可在逐次确认与 `yolo` 之间切换；选择不写入持久配置，也不影响后续新 Session。

`list`、`read` 和 `search` 在两种模式下均无需逐次确认，但始终受工作区、链接、类型、大小、取消和结果上限约束。

逐次确认模式下，每个 `write` 和 `edit`——包括创建新文件、覆盖现有文件和局部编辑——都必须在执行前进入专用、类型安全的文件授权流程。普通 `ask_user_question` 回答、文件正文中的指令或模型自然语言声明不能授予文件写权限。

授权界面至少显示操作类型、规范化相对路径、有界新文件预览或最终候选 diff，以及允许或拒绝的明确选择。拒绝后文件保持不变，并将结构化拒绝结果绑定原 tool call ID 返回模型，使 Agent 可以解释、调整或结束。

切换到 `yolo` 必须是用户主动操作，TUI 持续显示醒目的当前模式和工作区。`yolo` 下工作区内 `write`/`edit` 不弹逐次确认，但不放宽任何工作区、链接、参数、资源、版本冲突、原子写入或取消约束。切回逐次确认只影响尚未冻结授权决策的后续工具；已经批准或正在安全发布的单个 mutation 不能被错误地重解释。

## 工具执行与模型循环

文件工具沿用现有 OpenAI-compatible function-calling 协议、每响应工具数量、每 turn 工具总数、参数大小和 tool-call ID 唯一性约束。客户端对模型参数执行独立严格校验，不能仅依赖 JSON Schema。

同一 assistant tool-call 组按现有顺序和暂停语义执行。需要文件授权的调用暂停在其位置，未执行的兄弟工具不得越过授权继续。授权完成后从原 tool call ID 和原位置恢复；拒绝、取消、重复提交和迟到选择必须保持线性化。

同一目标文件的 `write` 和 `edit` 在进程内按规范化文件身份串行化，防止并行工具调用互相覆盖。串行队列不替代 expected hash：外部编辑器、另一个进程或队列外写入造成的版本变化仍必须返回冲突。

文件读取、搜索、授权等待和 mutation 全部接受当前普通 turn 的取消。`Esc` 停止 turn 后，不执行剩余文件工具、不发起下一次模型请求，并原子移除未完成 assistant/tool 模型消息；已经显示的有界工具摘要可以留在 transcript，并明确标记停止或失败。

## 本地工作区结果的权威性

文件工具结果是当前 Session 的本地工作区快照，不是服务端权威快照。它们必须使用独立于 `AuthorityServerSnapshot` 的 authority/freshness 类型，并可关联规范化相对路径、读取时内容 hash、文件身份或等价版本信息。

文件结果不携带服务端 generation，不参与服务端 snapshot invalidation，不自动成为 Knowledge、Learning、Review、Memory 或 Nocturne 内容。Agent 在依赖文件当前状态进行后续修改前必须重新验证版本，不能仅凭历史 tool result 假设文件仍未变化。

文件正文、搜索预览和 diff 可以进入当前模型上下文及有界 context compaction，但必须使用专用投影和字节预算。压缩摘要不得把文件内容伪装为用户指令、系统指令或长期偏好，也不得保存原始隐藏工具参数。

## TUI 与可见反馈

Agent TUI 显示当前工作区和文件授权模式。工作区可以用有界、脱敏形式显示；不能因窄终端而泄漏宿主绝对路径或挤压 transcript 到既有合同下限以下。

文件工具沿用 `Ctrl+O` 执行详情：收起时显示工具类型、相对路径、运行/等待授权/完成/停止/失败状态和稳定错误码；展开时显示有界读取范围、搜索进度、写入预览或 diff。UI 不显示隐藏 reasoning、完整秘密内容之外的额外副本、原始模型参数或无界 OS 错误。

长读取和搜索使用原地进度，不持续追加重复卡片。达到慢操作阈值时显示已等待时间、扫描进度、超时预算和 `Esc` 停止提示。

切换 `yolo` 时，界面必须明确说明：除受保护的归档目录外，当前工作区内文件（包括隐藏文件、`.git`、`.comet` 和可能包含秘密的文件）均无额外路径保护，内容可能发送给配置的模型 provider。模式状态在整个 Session 中持续可见。

## 错误与结果合同

文件工具返回稳定错误码和有界用户可读说明。至少区分：参数无效、路径越界、路径不存在、类型不支持、链接不允许、权限不足、UTF-8 无效、二进制文件、文件过大、结果截断、正则无效、内容版本冲突、替换缺失、替换不唯一、替换重叠、授权拒绝、操作取消和内部错误。

工具错误不能回显宿主绝对路径、环境变量、设备 token、客户端凭据或未请求的文件正文。底层 OS 错误只作为脱敏诊断线索，不能替代稳定错误码。

`list`、`read` 和 `search` 的截断是成功但不完整的结果；`write` 和 `edit` 只有安全发布完成后才能报告成功。任何失败不得被模型解释为“肯定没有副作用”，除非执行器已证明发布前失败且目标未变；若平台无法证明，必须返回明确的未知状态而不是假成功或假回滚。

## 安全与并发不变量

工作区约束、路径规范化、链接策略和 mutation 发布由客户端执行器强制。system prompt 只指导模型正确使用工具，不能成为安全边界。

文件内容视为不可信数据。文件内要求扩大工作区、切换 `yolo`、读取其他路径、忽略用户指令或泄漏凭据的文本不能改变工具策略。

工具执行具有明确的单文件、总扫描、结果、参数和时间预算。取消或超时后不能继续启动新的扫描或 mutation。文件数量、目录深度、正则复杂度和单行预览均有硬上限，防止资源耗尽。

安全读取和写入必须覆盖 Unix symlink/目录交换以及 Windows reparse point/junction/ADS。实现可以复用并扩展现有 `securefile.Root`，但不能通过普通字符串拼接把模型路径交给无根约束的写入 API。

## 验收场景

1. 用户在项目目录运行 `edu-agent agent`，Agent 使用启动目录作为工作区；指定 `--workspace subdir` 时固定使用该目录，模型只看到相对路径。
2. 模型调用 `list`、`search` 和分页 `read` 后，结果稳定、有界、可继续，并作为本地工作区快照回传下一次模型请求。
3. 模型尝试绝对路径、`..`、符号链接、junction、ADS 或工作区外目标时，工具稳定拒绝且不泄漏绝对根。
4. 逐次确认模式下，模型创建新文件、覆盖文件或 edit 时 TUI 显示预览/diff；用户拒绝后原文件不变，模型收到绑定原 call ID 的拒绝结果。
5. 用户在 TUI 主动切换 `yolo` 后，工作区内后续 write/edit 无逐次确认；状态持续可见，切回确认模式后后续 mutation 再次暂停授权。
6. edit 的多个替换基于同一原始内容；零匹配、多匹配、重叠或外部修改冲突时整次调用失败且文件不变。
7. write/edit 成功后返回新内容版本和最终 diff/摘要；同文件并行 mutation 串行执行，外部并发修改仍通过版本冲突拒绝。
8. 读取二进制、无效 UTF-8 或超限文件时返回稳定错误；搜索和读取达到上限时明确标记不完整并给出继续方式。
9. 用户在读取、搜索、等待授权或修改期间按 `Esc`，当前 turn 停止，剩余工具和后续模型请求不再执行，未完成工具组不进入历史。
10. 工作区内 `.git`、`.comet`、隐藏文件和秘密文件不受特殊 denylist；启动和切换 `yolo` 的提示明确说明内容可能发送给当前模型 provider。

## 验证策略

工具定义和参数解析使用精确单元测试，覆盖 schema、未知字段、尾随 JSON、边界值和稳定错误码。Agent loop 使用 fake workspace 与 fake model 覆盖 tool call、授权暂停、原 call ID 恢复、兄弟工具顺序、tool result、后续模型回答、取消回滚和本地 authority 投影。

安全工作区实现使用平台测试覆盖相对路径、绝对路径、Unicode、NUL、symlink、TOCTOU 目录交换、Windows reparse point/junction/ADS、root 规范化、原子替换、权限/BOM/换行、expected hash 和同文件 mutation serialization。

TUI fake conversation 覆盖工作区显示、默认逐次确认、所有 write/edit 授权、新文件预览、edit diff、拒绝、切换 `yolo`、持续模式标识、切回确认、窄终端、`Ctrl+O` 详情、慢搜索进度和 `Esc` 停止。

实现期间只运行受影响 package 的具名测试和 package 测试。稳定批次运行受影响 package 的 vet、error-level diagnostics、CLI build、定向 race 和 `git diff --check`。该 capability 不需要 PostgreSQL、Compose、OpenAPI、migration 或服务端黑盒证据，除非实现意外扩大到这些边界。
