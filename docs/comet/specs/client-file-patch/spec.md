# 补丁与完整差异（Issue #1 C6）

状态：生产闭环及Linux批次门禁已完成；尚未通过Runtime、macOS原生或整个Issue最终验收。实施细节及验证记录见[交付设计](../../../design/client-local-tools-delivery.md)。

目标：模型和用户能核对write/edit及关联多文件文本补丁的完整差异，一次授权后得到逐文件真实结果。

1. write/edit保留兼容入口，新增apply_patch支持多个文件的新增、修改和文本删除归档；支持多hunk，不提供二进制补丁、Git index或模糊匹配。
2. 补丁明确携带现有文件完整内容版本；修改上下文精确且无歧义，路径遵循现有root/no-follow/归档保护规则，不借Shell绕过。
3. 全部文件预检并冻结版本、候选和完整差异后才进入授权；已知上下文、版本、目标或计划内路径冲突均不开始发布。
4. 一次授权覆盖整个冻结计划；完整差异可分页浏览，但不新增必须浏览末页的批准门槛。YOLO与恢复重置保持。
5. 完整diff独立于聊天摘要，模型及TUI均能继续查看；游标对应实际返回字节，投影缩短不跳过内容。
6. 逐文件版本复核及原子发布，已完成文件不自动回滚；冲突、取消、失败或未知时停止剩余项。
7. 每文件分别报告完成、未变更/拒绝/冲突、失败、未知与未尝试，并保留实际路径、版本及归档位置；不得只返回最后文件或笼统成功。
8. 每次实际发布前保留文件WAL，发布后记录真实结果；持久化失败不继续剩余文件，模型失败不抹去已发生副作用。
9. 恢复不自动应用旧补丁，未结算的文件操作为unknown；已经保存的差异/结果仅作为数据，不恢复可执行候选或授权。
10. 持久Session的差异/逐项结果沿用Session-owned加密产物、独立配额、delete/clear及generation边界；正文不进入稳定checkpoint、标题或明文sidecar。
11. --no-save的差异/结果仅内存保留，退出不可恢复；没有隐藏的临时历史文件。
12. 原文/候选、补丁参数、完整差异和历史保留分别有明确预算；超限或保存失败明确可见，不静默删旧结果，不将截断内容称完整。准备时无法保留完整差异则不发布目标；不确定保存留下的孤儿片段不能被提升为完整结果，也不能因对话为空而自动删除。
13. BOM、未修改原字节、换行、末尾换行与普通权限的既有合同保持；全文件IO和内存仍有界，不承诺任意大小流式修改。
14. 人工完整差异查看不调用模型；目录/二进制操作维持其已有操作清单，不伪造文本diff。
15. 验证须覆盖真实多文件的模型调用→完整差异查看→一次授权→逐项WAL/实际发布→结果及恢复；包含预检失败、发布中冲突/取消/故障和投影裁剪。

范围外：通用内容上传、跨文件事务、自动回滚、补丁重放、Windows扩展、全屏终端或新的服务端数据权限。
