# 大文本局部编辑（Issue #1 C5）

状态：生产垂直路径已实现，并通过Linux批次门禁；用户已确认v2轻量方案，不代表Runtime、macOS原生或整个Issue #1最终验收通过。技术与批次边界及运行证据见[交付设计](../../../design/client-local-tools-delivery.md)。

目标：模型以局部old_text/new_text修改超过1MiB的普通UTF-8文本，无需回传完整文件；保留现有结构化文件安全合同。

1. 在独立编辑处理预算内，edit可修改超过1MiB的文件；模型只需提供局部替换与完整expected_hash，不以单次参数预算限制原文件大小。
2. 所有替换均对同一原文精确匹配，要求唯一、不重叠；缺失、重复、重叠、无变化或非法文本不发布，不加入模糊匹配。
3. 替换位置可跨越1MiB边界或分布在文件远端；不改变未修改区域的原字节。现有BOM、替换文本的换行归一、权限与末尾换行合同保持。
4. 原文件与最终候选各自受明确的完整字节预算约束，包含BOM及换行归一后的字节；超限在授权/发布前明确拒绝并指向调参或Shell替代。
5. 单次完整arguments JSON仍为64KiB，单批仍为128KiB，最多32处替换；不把处理较大原文件当作扩大模型传输预算。
6. prepare不改变目标；发布前保留既有安全入口、内容版本及候选/预览完整性复核，授权后外部变化不能静默覆盖。
7. 保持同目录临时文件完整写入、同步及安全原子发布，不改成就地写；取消、冲突、失败及未知结果与实际磁盘状态一致。
8. 默认仍一次文件计划确认，YOLO及恢复重置策略不变；不增加逐页审批。当前预览可以有界截断但必须明确，完整diff由C6交付。
9. 执行前必须成功保存现有文件WAL，执行后记录真实结算；模型/保存失败不能抹去已发生修改，恢复不自动重放。
10. CLI编辑预算对新建、resume及F2切换生效，使用当前客户端设置，不随历史Session恢复旧预算或扩大权限。
11. 路径、归档保护、链接与特殊入口拒绝规则保持；扩大编辑预算不赋予工作区外结构化文件访问权限。
12. 不保存完整候选/原文到新的历史sidecar，不把原始编辑参数或完整预览正文扩大塞入稳定恢复记录；现有有界元数据/投影合同保持。
13. 本批不扩大write、stat.hash、search的预算；read继续使用C4独立预算。Shell保持独立的正常本机权限合同。
14. 验证必须覆盖模型调用到授权、真实大文件发布、客户端结果与恢复记录，并覆盖拒绝、取消、冲突和WAL失败；不能仅以底层API或schema存在作为完成。

非目标：通用流式匹配/上传、固定内存GB级修改、跨文件事务、原地写入、模糊修复、patch及完整diff留存、服务端/数据库变更。
