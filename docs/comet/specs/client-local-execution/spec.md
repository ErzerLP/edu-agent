# 客户端本地 Shell 与受管任务

状态：Issue #1 已确认 C1 用户合同；C1 生产路径已实现并通过 Linux 批次门禁，不是已通过 Runtime 或 macOS 原生验收的声明。设计和后续单元见 `docs/design/client-local-tools-delivery.md`。C2 的持久完整输出、C3 的 PTY 单独交付，本规格不得被误解为整个 issue 已完成。

## 结果与范围

用户和模型能够在 Linux/macOS Go CLI 中运行正常本机 Shell，观察并继续管理长任务、提供管道 stdin、读取当前进程保留的输出和停止任务。文件工具与服务端既有权限和授权规则不变。

## 必要合同与验收

1. Shell 使用启动客户端的 OS 用户权限，不增加命令白名单、工作区围栏、网络限制或默认逐命令审批；正常支持管道、重定向、脚本及已安装工具。TUI 和工具说明明确文件确认模式不约束 Shell。
2. 可指定 cwd、Shell、环境变量覆盖/删除；默认 cwd 不可用时错误，不静默改为另一个目录。不会额外注入钥匙串中的客户端凭据。
3. 每次命令是独立 Shell，不继承前一次 cd/export/alias。非交互、非 login；返回实际选择，输入模式明确。
4. 启动命令获得有归属的稳定任务标识。重复同一次调用身份不重复执行，不以命令文本去重；未知不能冒充已完成。该保证不依赖输出是否成功保存，恢复不能遗失旧调用身份；合法新调用仍可执行。
5. 一次等待预算与执行超时分离；默认不设执行总时限。等待结束返回仍在运行，取消等待不暗中终止后台任务。
6. stdout/stderr 按各自实际字节顺序记录；任务执行状态与输出可用性分开。退出码仅在实际取得时返回，启动失败、非零退出、运行、完成、取消、超时、未知可区分。
7. 可通过模型或客户端界面查询、分页读取当前进程中的已保留输出、等待和停止任务；查看和停止不依赖模型请求成功，也不要求任务先结束。
8. 管道 stdin 可显式保持打开并多次写入、关闭。单次输入有预算但累计可超过 64 KiB，最终文件可核对；失败/取消不伪称输入完整，不自动重传可能已经写入的内容。
9. 受管命令使用独立进程组。停止处理普通子进程，有限宽限后升级终止；无法证明清理完整时报告限制，不能只结束 Shell PID 就称清理成功，也不向恢复记录中的旧 PID 发信号。
10. 输出与并发任务资源预算明确可配置。配额耗尽不自动淘汰旧输出；继续排空管道并报告缺口，不用日志预算暗中杀命令。额外启动被资源预算拒绝时没有启动副作用。
11. 模型失败、轮次取消和历史压缩不抹去已发生的任务事实。恢复不自动重跑历史命令，C1 的进程内输出在重启后明确不可访问，执行结果缺乏证据时明确未知。
12. 符合既有空闲切换门禁时，后台任务仍归属原 Session 并在客户端中管理。正常退出停止受管任务、结算后关闭资源；不先销毁数据所有者。
13. 不自动保存原始命令参数、环境、stdin、原始 OS 错误或完整工具输出到现有历史 DTO。任务摘要不得成为服务端权威状态；终端呈现必须处理控制字符。
14. `--no-save` 自动采集的输出仅保留在内存，不创建临时历史文件；Shell 本身显式文件副作用仍正常执行。
15. 旧文件工具、YOLO 恢复重置、provider 历史发送确认、Session 在用/删除边界保持；Shell 注册不依赖安全 workspace executor 可用性，但缺失默认 cwd 时应要求显式 cwd。

## 不属于 C1 的内容

PTY、重启后完整输出读取/检索、常驻守护进程、跨进程重新附着、自动重放、Windows 支持、改造文件权限、服务端业务权限变更。后续 C2/C3 到达稳定生产路径并验收后再更新相应完整合同。
