# 客户端 PTY 交互任务

状态：Issue #1 已确认方案的 C3 用户合同，生产闭环及Linux批次门禁已完成；不代表整个 issue 或原生多平台验收完成。

## 结果与范围

用户和模型可让需要真实终端的本地程序在受管 PTY 中持续运行、输入、调整尺寸、发送终端中断/EOF 并查看合并输出。复用正常 Shell 权限和 C2 加密输出；不做常驻 daemon、跨进程附着或完整终端屏幕模拟器。

## 必要合同与验收

1. 显式选择 PTY 后，子程序的 stdin/stdout/stderr 是同一真实控制终端；缺省仍为 C1 pipe，不静默把 pipe 换为 PTY。
2. 初始终端尺寸可指定，缺省有明确值，非法尺寸在执行前拒绝；运行中 resize 对程序可观察。
3. 每次 shell 调用仍是新进程，不自动附加交互/login 参数。需要持久 Shell 状态时显式启动交互 Shell，并持续使用同一 task_id。
4. PTY 自带持续输入通道，支持多次输入；真实接受字节数与程序处理结果分开，部分/取消/失败不自动重传。
5. 中断发送终端当前 VINTR 控制字符；EOF 发送 VEOF。正常 termios 的 canonical/raw/disabled 语义保持，不保证发送后程序一定结束。
6. PTY EOF 与关闭 pipe stdin 不混淆；不能为了伪造 EOF 关闭仍在采集的 master 而隐瞒输出损失。
7. stdout/stderr 合并后只有一个有序输出流；模型和 F5 明确标识，不能把空的独立 stderr 当作“没有错误输出”。C2 分页、检索、保存配额及缺口语义继续有效。
8. F5 提供显式进入的行式终端输入模式，可发送一行、终端中断及 EOF，不必等待模型成功返回。它不是原始按键直通或全屏终端模拟器。
9. 输入模式内 Ctrl+C 发送终端中断，Ctrl+D 发送 EOF；Ctrl+Q 仍退出客户端。Esc 可退出输入模式，关闭面板不等于撤销已发送输入；未知输入不能自动重发。
10. 人工输入直接发送到当前任务，不加入模型调用、chat/source 或恢复重放队列。目标程序正常回显属于真实输出，可能按 C2 加密保存；不承诺过滤程序自行输出的输入内容。
11. 模型发起的输入及终端控制继续遵守无可执行正文的本地任务意图记录和失败保留路径；终端输出不是模型指令或服务端权威依据。
12. stop、执行超时及客户端退出仍处理普通子进程；交互 Shell 的 job-control 分组不能因为根进程组空就伪报清理完整。无法证明结束/清理时明确 unknown/incomplete。
13. 只使用当前活跃任务拥有的终端/进程能力；已结束、历史、未知或别的 Session 的任务不能接收输入、resize 或信号，不使用历史 PID。
14. 持久历史识别 PTY 合并模式并能读取已保存输出，但不能恢复控制。C2 v1 的 pipe 产物仍可读取；新版本不伪装成旧格式，未来版本安全拒绝。
15. no-save 的 PTY 输出仍仅内存，输出正文不自动进入 checkpoint、标题或压缩。终端控制序列安全呈现，不直接回放。
16. 尺寸、输入、关闭和输出并发时不错误复用 FD/PID；迟到的界面回复不能串入新的任务、面板或 Session。关闭查看不谎称任务已取消。
17. C1 普通 Shell、pipe stdin、等待取消、文件授权与 C2 保存/检索/隐私边界保持不变。仅支持 Linux/macOS，不扩大 Windows 承诺。
