# Shape：在 AI 对话中学习的 Notebook 式学习区

状态：Shape 已确认（2026-10-13）：用户认可对话式原型 v2，Q1–Q5 采用建议默认值。

调查基线：`docs-shape-chat` / `493aaa5`（main 已合并批次 1、2、3）。已交付来源目录 G1、四种来源入口 G2、来源问答与引用 G3，以及 Studio G4–G6；新对话教学尚未实现。用户 2026-10-12 的方向决定优先于旧 Shape。此次仅修改 brief、spec 和设计文档，不改代码、测试、OpenAPI、migration，不执行 Git 暂存或提交。

## 结果

用户创建一个学习区、填写宽泛的学习方向，在“来源 — 对话 — Studio”中学习。导师依据方向与当前所选资料讲解、追问并插入练习卡；用户在卡片内答题、选择实际帮助等级、提交，随后在对话中看到反馈。练习进入既有学习记录、进度与复习，用户无需选择或管理后台教学目标。

## 范围

- 学习区仍与 learning space 一一对应，复用首页卡片墙、生命周期、三栏与手机标签。
- 创建时填写学习方向，在学习区设置中随时修改；系统维护后台目标及版本，保留旧活动和记录。
- 中栏改为连续 AI 对话，提供内嵌练习和反馈卡；来源勾选决定之后发起的对话、出题与 Studio 生成。
- 保留 PDF、文本、网址、搜索发现、解析审阅、可核验引用；保留学习指南、简报、测验、笔记与笔记转来源。
- 新增“学习端全权”配对档案，一次配对覆盖来源、研究／搜索、对话与练习、Studio、长期记忆候选等学习侧操作；管理后台登录和隐私清除 grant 独立。
- 保留进度与复习、评估与证据、历史、长期记忆、任务、知识维护、NoteSync、离线、设置、数据与设备等辅助入口及已有深链接。

## 非目标

- 不动 CLI；不改变旧调用的缺省语义，不要求 CLI 配合新增字段。
- 不重写评分、Evidence、掌握度或复习算法，不从聊天次数、生成题目、阅读或跳过推断掌握。
- 不建设第二套 notebook／知识库，不新增音视频概览、思维导图、闪卡、协作分享或离线对话教学。
- 不新增 OCR、Office 解析、网页执行、登录抓取或自动加载外部图片。
- 不清空旧目标、课堂、来源或 Studio 数据；不逐页重做辅助功能。
- v1 [原型](../../../design/notebook-workspace-prototype.html)仅保留布局参考。v2 预期路径为 `/home/yunyue/.config/edu-agent-demo/prototype/v2/index.html`，本次调查时不存在；不以等待原型阻塞文档，也不复制其假数据与模拟成功。

## 关键决定与替代关系

| 决定 | 本轮有效要求 | 与旧 Shape 的关系 |
| --- | --- | --- |
| N1 对话为主 | 中栏为 AI 对话；去掉“今天想学会什么”、目标选择／创建／搜索分页和课堂工作流步骤。移除常驻解释性文案；必要错误、外发授权、导入审阅、帮助等级仍可操作。 | 替代旧选项 B、“目标 → 课堂”主路径及旧 spec 3、5、13 的入口语义。 |
| N2 学习方向 | 方向可以宽泛、随时修改；后台目标由系统依方向维护，旧活动保留原版本。 | 替代 D4 的“先手工建目标才能开课／测验”；不再禁止有真实方向依据的系统目标。 |
| N3 内嵌练习 | 对话中的练习提交仍经既有活动、评估、证据与复习路径；优先复用 3c 方案 A 的单题会话桥接。界面使用“练习／提交／反馈”，不暴露“正式／冻结／档案”等后台术语。 | 扩展 D2；保留真实记录、实际帮助和有效证据才影响掌握的规则。 |
| N4 来源实时选择 | 当前勾选决定之后发起的对话、出题与 Studio；已经发出的题按出题时资料评估，已受理的请求不被中途改选重写。 | **D1 的“课堂冻结、勾选只影响追问”界面语义废止**。保留后台按请求、按题保存版本及引用验证。 |
| N5 学习端全权 | 新档案显式组合学习侧 scopes，不升级旧设备，不授予管理后台身份或隐私清除 grant。 | 替代“只能分别配对学习能力”的产品限制；各端点权限与领域确认继续有效。 |
| 保留项 | 来源 G1–G3、Studio G4–G6、D2 的记分边界、D3 的已保存笔记版本转来源、安全与兼容验收继续有效。 | D3 中“采用到课堂”改为新来源参与当前选择；快照复制、审阅与幂等不变。 |

建议后台采用“一个学习区一个系统管理目标，方向变化产生目标修订，单题会话绑定具体修订”。对话与题目有各自持久身份，提交后自动编排评估并读回反馈。协议、状态与替代方案放在[设计文档](../../../design/notebook-workspace.md)，不在 brief 展开。

## 端到端验收示例

- 一次“学习端全权”配对后，创建“线性代数”学习区并填写方向，导入 PDF／文本，直接在中栏交流。导师讲解并给出练习卡，用户选择实际帮助、提交后收到反馈；进度页能读到同一作答，符合证据规则时进入复习。
- 来源 A 下发出题目，改选 B 后继续交流、出新题与生成简报，均使用 B。提交旧题仍依据 A 和原评分标准评估；界面无需解释后台版本机制。改选不会把旧来源正文或旧反馈偷偷发送给新对话。
- 在设置修改方向，下一轮导师依据新方向教学；已有题、反馈和 Studio 历史不被改写。保存的对话可重开；聊天输入不会自动成为练习答案。
- Studio 测验无需手工选目标，仍以单题会话逐题作答。提交响应丢失后核对原操作，只产生一次 Attempt；评估尚未完成显示实际状态，不伪报得分或完成。
- 保存笔记 v1 并审阅转为来源，编辑到 v2 不改变已导入副本。手机打开引用再回对话保留草稿；撤权或隐私清除后，迟到响应不恢复正文。

## 用户已确认（2026-10-13，采用建议默认值）

用户已确认全部采用下列建议默认值。原型见 [notebook-chat-prototype.html](../../../design/notebook-chat-prototype.html)。

| 编号 | 问题 | 已确认的默认值 |
| --- | --- | --- |
| Q1 | 已有学习区如何补方向？ | 保留旧数据；首次使用新对话时以区名预填方向供一次确认，不从旧目标或私人描述自动推断。之后在设置修改。 |
| Q2 | 未选来源时是否允许出计入记录的练习？ | 可以一般对话；首版不出此类练习，也不生成依赖资料的 Studio 产物。用户请求时给出简短添加／选择来源入口，无常驻“未选来源”解释。 |
| Q3 | 新学习对话是否默认保存？ | 默认保存已发送的对话与卡片，保留新建／切换对话；未发送草稿仍只在标签页内存。旧临时对话不自动转为保存。 |
| Q4 | 导师自动出题的节奏？ | 每轮最多一题、每个对话同时一张待答卡；允许“稍后再做”再继续交流，不记作完成。首版为开放文字题。 |
| Q5 | “学习端全权”是否包含模型／搜索配置写入？ | 包含学习业务、记忆候选审阅和设备撤销；暂不含 settings 写入／探测，沿用独立 settings 授权。管理后台与隐私清除 grant 继续独立。 |

## 拆分与 Ready 结论

按[工作流](../../../development/development-workflow.md)保留 Supervisor Shape：新结果分为 C1 学习端全权配对、C2 方向与连续对话、C3 内嵌练习完整闭环、C4 Studio 接入方向、C5 移动与候选收口。共享接口与 migration 的工作串行；C3 必须同时交付出题、作答、评估、反馈与进度读回，不能以只有卡片或表的批次退出。

父级 [spec](spec.md) 30 项描述归档后的行为，已交付部分仍需回归，新要求不冒充已完成。每个 child 目标为 10–30 项；超过 40 项或需要三个以上独立重型矩阵重新拆分评估。估算与退出标准见设计文档。当前处于待确认 Shape，Q1–Q5 及第一批公共合同确认后才进入相应 Build；本次不创建 Runtime 状态，不手写 verification。
