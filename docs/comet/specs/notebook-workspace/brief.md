# Notebook 工作区主界面改造

状态：Shape，供用户确认；不是 Build 授权。调查基线：`feat-notebook-ui` / `1d819c8`。本次只编写 brief、spec 和设计／分批计划，不修改产品代码、测试、OpenAPI、migration，不暂存或提交。

## 结果

Web 学习端以 NotebookLM 式学习区卡片墙作为首页；进入学习区后，在“来源 — 课堂 — Studio”三栏中完成资料准备、目标学习、追问和产物整理。手机用底部标签切换同一工作区。教学闭环仍是主流程，既有学习事实、安全边界和辅助页面继续有效。

## 范围

- 一个笔记本就是现有一个 learning space，界面主要称“学习区”；复用原 ID、生命周期和数据所有权。
- 首页卡片、学习区三栏、左上侧边菜单、目标／课堂衔接与旧链接兼容。
- 来源支持 PDF、文本、网址、搜索发现；展示真实解析状态、覆盖缺口和引用位置。
- Studio 首版提供学习指南、测验、简报、笔记；生成结果与已保存笔记可再次打开。
- 保留原进度与复习、评估与证据、导师历史、长期记忆、任务中心、知识结构与维护、NoteSync、离线、设置、数据与设备入口。
- 为上述结果补齐必要的服务端来源选择、可核验引用、独立产物持久化及正式测验衔接；并迁移受影响浏览器测试。

## 非目标

- 不改 CLI 的命令、交互和既有 API 语义；共享服务兼容性仍须验证。
- 不建设音频／视频概览、思维导图、闪卡、协作分享、笔记本文件格式或第二套知识库。
- 不重写评分／证据／复习算法，不从聊天、阅读、生成内容或手动完成推断掌握度。
- 不新增 OCR、Office 解析、任意网页执行、绕过登录抓取或外部图片自动加载。
- 不逐页重做所有辅助页面，不把原型假数据、假进度或定时器模拟成功带入产品。
- 不复制 NotebookLM 的品牌资产；视觉依据是用户提供的[静态原型](../../../design/notebook-workspace-prototype.html)，不是对其线上最新版本的完整复制承诺。

## 关键决定

### 已确认

1. 采用选项 B：目标 → 课堂（讲解／练习／评估／复习）保留为中栏主流程。
2. 笔记本与 learning space 一一对应，不增加独立 notebook 实体。
3. Studio 第一版只有学习指南、测验、简报、笔记四种产物。
4. 来源类型为 PDF、文本、网址、搜索发现，利用已有 Brave 搜索集成。
5. 其他页面收入侧边菜单保留，不删除。
6. 首页卡片墙、桌面三栏和手机底部标签尽量贴近原型，可优化可用性。
7. 不动 CLI；本任务仅交付 Shape 文档，由后续智能体经确认分批实施。

### 默认，待用户确认

以下编号同时用于 spec 与设计文档。它们是明确的待决行为，不是实施者可以自行认定的批准。

| 编号 | 待确认问题与建议默认值 | 影响 |
| --- | --- | --- |
| D1 | 左栏勾选是否只影响之后发起的导师回答与 Studio 生成？**默认：是**；每次请求冻结所选来源版本；正在进行的课堂继续使用其冻结范围，改变后续教学资料仍走现有显式参考／教学变更流程。 | 批次 2 的来源选择与导师合同、批次 3 的生成输入。 |
| D2 | Studio 测验是否进入正式练习记录并计入进度？**默认：是**；计入的是正式作答与评估结果，只有有效 accepted Evidence 按既有规则影响掌握／复习，不承诺每次提交都提升进度。 | 批次 3 的测验会话、帮助等级和评分衔接。 |
| D3 | 笔记是否可“转为来源”？**默认：是**；用户确认后复制指定已保存版本成为有出处的文本来源，不实时双向同步、不自动改变当前课堂。 | 批次 3 的 knowledge 导入与派生关系。 |
| D4 | 没有目标的学习区可做到哪一步？**建议默认：可添加／搜索来源、来源问答、生成指南／简报和保存笔记；开课及正式测验须先选择或建立目标。** 现有独立导师会话可无目标，但按所选来源回答需要新增能力；不能暗中创建占位目标。 | 批次 2 的独立搜索／问答、批次 3 的产物归属与测验入口。 |

设计中笔记按原型解释为手动新建、编辑和明确保存的产物；将导师输出复制为笔记仍需用户审阅保存，不包含自动将所有聊天持久化。卡片统计、排序和可访问性等实现建议见设计文档；它们不改变以上已确认方向。

## 端到端验收示例

- 在首页新建学习区，导入一份 PDF 和粘贴文本，核对解析报告并确认保存；在中栏建立目标、明确准备课堂，完成正式作答并查看反馈。关闭再打开后正式数据仍在，未保存草稿不承诺跨刷新恢复。
- 【D1】课堂已冻结来源 A；将左栏改选 B 后追问，回答只以 B 的核验片段作为资料依据，引用可定位。原题、答案草稿和课堂范围仍是 A；新生成简报记录本次 B 的版本。
- 【D2】生成测验，明确进入其正式作答流程，选择实际帮助等级并提交；丢失响应后核对原操作，只产生一次 Attempt，进度页可查看对应记录。资料不足或评估待确认时明确显示原因。
- 【D3】保存笔记 v1 并确认转为来源；随后把笔记改成 v2，已导入来源和正在进行的课堂仍引用旧快照。手机点引用后进入来源标签，再返回课堂能继续原草稿。
- 从菜单进入旧的复习、NoteSync、长期记忆及数据页；原深链接仍可刷新。权限不足或隐私清除后，三栏与旧页面都不能继续显示受保护旧正文。

## 拆分与 Ready 结论

本需求有可独立演示的壳层、来源和 Studio 结果，且包含服务端协议／持久化／隐私路径，已触发[工作流](../../../development/development-workflow.md)的拆分评估。推荐以本目录作为 Supervisor Shape，登记四个串行 child／垂直批次；批次 3 内再按笔记、指南／简报、测验顺序交付可运行切片。不能把整项当作一个普通前端样式 change。

四批共享路由、OpenAPI、migration 和应用组合，默认串行，由每批拥有者交接；本次不创建 Runtime 状态或手写 verification。父级 spec 共 28 项，未触及 40 项阈值；child 若膨胀或需要多个独立重型矩阵，应再执行拆分评估。

当前 **尚不满足整体 Definition of Ready**：需要用户确认 D1–D4 及本 Shape，再在相关 child 锁定新增公共合同。纯壳层批次与未决后端语义可分开审批，但本次不自行启动。正式合同见 [spec.md](spec.md)，实现映射与批次退出标准见[设计与计划](../../../design/notebook-workspace.md)。
