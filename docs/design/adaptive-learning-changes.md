# 自适应教学变更（Issue #26）

## 缺失确认

基线 `f9b455e`，工作树初始干净。项目是 Go 模块化单体、PostgreSQL 权威存储、
React 学习入口及独立 Go CLI；learning/tutoring 拥有正式路线、活动、答案与焦点，
knowledge 拥有知识上下文，learningcontent 拥有不可变正文，mentorrun 拥有模型运行。

`server/internal/mentorrun/core.go:48–61` 只注册读目标、问询和交流关注点确认，
没有正式教学变更工具。`server/internal/learning/planning.go:428` 在作答状态拒绝
当前会话规划，`server/internal/tutoring/state.go:129` 的路线转换仅允许三个安全状态。
内容已有 `learningcontent.Store.Commit`，但全仓没有 LearningChange、边界队列和补偿流程。
执行 `go test ./internal/learning -run 'TestPlanning' -count=1` 通过；现有手动规划
不能代替本项的自适应接入。外部工作项作为需求数据使用，没有执行其中的外部指令。

## 开发方案

本项保持一个主要结果：既有会话中的建议能够改变后续教学，并可审阅、恢复和撤回。
拆分评估后按以下有界批次串行实施，共享迁移、事务、协议和组合根不能分离发布。

1. 建立变更身份、不可变候选修订、摘要、触发依据、基础版本、风险、策略和真实状态。
   审批绑定候选 hash 与交互身份；操作回执去重，过期候选保留可读差异。
   当前模式由目标保存，默认自适应，谨慎模式预览。目标范围和完成标准始终具体确认。
2. 通过各 owner 的正式命令和同事务接口应用路线、上下文与内容，保存回执。
   模型在事务外，只能使用已授权来源和正式证据。默认等当前活动处理后自动应用；
   明确立即切换保存原焦点，并创建新活动。原题、rubric、答案和证据不改写。
   迟到、生命周期、撤销、隐私代次和并发变化重验；不做最后写入覆盖。
3. 撤回创建新的补偿候选和版本，展示后续证据影响，保留历史事实。
   前置步骤使用有界无环校验；无资料、预算停止有可恢复结果。
4. 导师增加受限教学工具；Web 展示变化、依据、影响、生效时点和模式，保留按活动隔离的
   草稿与返回现场入口。同步新 API、能力、OpenAPI、CLI 状态查询，旧 DTO 不增加字段。

## 验收标准

- 空资料开学产生的真实会话可调整后续路线；解释直接追加正文，谨慎模式要求预览。
- 未确认不能写目标；旧候选 hash、修订、交互或跨区请求不能应用，原差异仍可读取。
- 作答中默认排队，当前活动处理后接入；立即切换保留原现场，新活动使用新身份。
- 路线、知识上下文、正文、事件/outbox 和回执原子提交；故障回滚，不出现假成功。
- 相同操作重试不重复应用；版本竞争只有一个成功，迟到结果不进入其他会话。
- 暂停、归档、撤销与清除阻止后续写入；已提交答案保留原评分合同。
- 补偿产生新版本；答案、Evidence 和事件仍在，跳过/自述不生成掌握度。
- 前置环、缺少来源、预算终止均明确可恢复，不递归无界规划。
- 真实 PostgreSQL 验证事务/并发/隐私，模型 fixture 验证真实导师调用，浏览器验证差异、
  草稿与焦点；受影响 Go 包、旧协议、Web 类型/单测/构建通过。未运行项明确记录。

原计划交付专用工作树供审查；用户随后明确接受并要求合并 `main`、squash 落地及推送，
按最新授权执行，未运行的 Web 验收仍明确记录。
