# 动态知识结构与维护（Issue #30）

## 缺失确认与原因

基线 `9a80ee4`，分支 `task/51`，初始工作树干净。
本项是功能请求，按生产入口和数据模型确认缺失：

- `server/internal/knowledge/context.go:14` 的 ConceptRevision 只有身份、语义键、名称和研究出处，没有关系、主张、条件、缺口或维护状态。
- `server/internal/knowledge/postgresstore/context.go:155` 按目标与显式语义键建立身份并追加版本；现有能力不能按名称推断合并，也没有用户审阅概念关系的路径。
- `clients/web/src/knowledge-page.tsx:26` 只提供集合、导入、冻结范围和参考角色，没有节点或维护审阅入口。
- `server/internal/knowledge/maintenance_service.go:47` 调用 `legacyKnowledgeScope`；`server/internal/knowledge/scopes.go:12` 明确限制旧文档维护的默认映射。旧文档提案已经存在，应复用其服务，不能把它误当作概念维护已实现。

项目是 Go 模块化单体、PostgreSQL 权威存储、React Web 和独立 Go CLI。
knowledge 拥有概念、来源、版本、集合和知识维护；learning/tutoring 拥有证据、活动、路线和焦点；learningcontent 拥有不可变正文；learningchange 是 #26 的安全教学接入协调者。当前没有本任务的 Comet brief/spec，直接按用户给定 issue 范围执行，不改历史归档。

## 开发方案

保持一个主要结果：用户能查看并审阅本学习区逐渐形成的知识结构。共享 schema、协议和事务使三个批次需要串行推进。

1. 在现有概念与不可变修订上追加结构字段和版本头；保留旧研究出处。节点支持多个明确章节出处、主张/条件/缺口、来源状态、AI 建议标记、前置/相关/对比/组成关系。名称不参与身份合并。服务先限定学习区与授权出处，再分页和投影局部边；不递归展开、不引入图数据库。
2. 由现有 knowledge owner 提供结构提案创建、列表、详情、批准/拒绝、补偿。冻结前后版本、理由和影响；操作 ID 幂等，批准时重验版本、出处和依赖。合并/拆分显式保存旧身份到新身份的映射；从不复制 Evidence。文档维护继续调用已有 Create/List/Get/Decide/CreateRollback，不改变旧 CLI DTO。
3. Web 知识页与教学侧栏复用列表/局部图，提供可键盘操作的等价入口。独立呈现来源状态和学习证据；冲突展示具体主张、出处与条件，允许修订说明、进入研究与参考角色管理。维护改变可用上下文，通过 #26 审阅后接入后续教学，保留当前活动和草稿。

迁移只追加；新增知识 payload、关系、回执和索引纳入现有隐私 owner 的屏障、清除与残留核验。响应与前端查询不持久缓存正文。回滚追加补偿版本并重新计算当前依赖，绝不删除学习历史。

## 验收标准

1. 同名节点拥有不同 ID；同一节点支持多份来源、多章节，伪造及跨区引用失败。
2. 列表和图使用同一次服务端投影；分页、过滤、局部边裁剪和版本变化有明确提示，环不会导致递归或无界读取。
3. 来源/内容状态与学习状态分别显示，AI 建议和来源采纳不产生掌握标记。
4. 冲突包含具体主张、条件、出处、缺口；修订需要正式提案，研究与参考排除/角色调整有入口。
5. 维护、合并、拆分与补偿可创建、审阅、批准、拒绝；旧引用可追溯，未批准不改正式节点。
6. 同一操作重试不重复写入；并发基础版本仅一个生效；新依赖使旧提案过期并显示当前影响，响应丢失可核对原提案。
7. 影响展示目标、context、活动和内容；未来教学经 #26 接入，当前题、答案和 Evidence 不被改写或复制。
8. 新概念版本不继承旧概念的评估结论；补偿也保留全部学习事实。
9. 解除集合引用、移除知识关系和隐私清除语义不同；共享关系不扩大读取权限。
10. 隐私清除覆盖全部新增 payload、关系、索引及浏览器缓存；旧版本和图不可恢复正文。
11. 真实 PostgreSQL 覆盖维护/版本/并发/隐私，浏览器覆盖图/列表/键盘/审阅；旧 CLI 合同、受影响 Go 测试/vet/build、Web 类型检查/单测/build 通过。
12. 同批更新 OpenAPI、能力查询、迁移说明和使用文档；未运行的检查如实记录。

## 交付边界

本任务不创建固定课程树，不增加掌握算法或跨目标证据继承，不自动批准研究覆盖原文。结果保留当前工作分支供用户落地；不合并、rebase 或推送基础分支。
