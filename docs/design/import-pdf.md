# 文本层 PDF 导入与版本引用（Issue #29）

## 缺失确认

基线 `1d0861d`，工作树干净。服务端是 Go 模块化单体，PostgreSQL 保存权威数据；
Web 使用同源配对和既有导入预览，CLI 读取规范 Markdown。knowledge 拥有文档身份、
不可变版本、冻结范围、索引和清除；research 拥有逐跳网络边界；learningcontent
从已验证引用重新读取原始版本，mentorrun 不能自行扩大导入权限。

基线 `server/internal/research/fetch.go:191–199` 的 MIME 白名单只接受 HTML/纯文本/Markdown；
`server/internal/knowledge/domain.go:135–139` 的 ImportDocument 只有 Markdown 正文；
`clients/web/src/lib/reference-import.ts:27` 在读取文件前排除 PDF。
执行 `go test ./internal/research -run '^TestFetchParsingLimitsAndRestrictions/PDF$' -count=1 -v`
通过：该测试明确断言 PDF 返回 `unsupported_format`。并无另一设置提供 PDF 能力。

## 开发方案

保留一个垂直结果：用户把 PDF 的实际文本作为可选参考，并可核对旧版本的原始页。
解析器、来源合同、预览确认、版本存储、引用、Web 和清除共享同一输入及版本关系，
因此在本分支串行完成，不拆为无法独立验收的横向子任务。

1. 在无宿主文件系统、网络、Shell 或脚本执行能力的 WASM 中运行固定版本 PDFium。
   输入、页数、文本、像素、内存、并发与执行时间设硬上限；逐页报告提取状态、
   物理页码、片段、指纹及可识别缺口。扫描件不做 OCR，复杂版式/公式/表格不承诺语义。
2. 上传与已授权网页抓取调用同一适配器；网页继续执行 SSRF、DNS、重定向及禁止留存检查。
   导入提交原始 PDF，由服务端重新解析，不能相信客户端或模型自报页码。
   部分结果必须明确选择；正式导入仍经父版本、身份审阅和预览确认。
3. 原文指纹和解析器版本参与规范正文身份，页范围绑定不可变文档版本。
   原文件和报告与正文同事务保存；旧题引用不随新文件漂移。原文派生与 AI 综合分开。
   安全查看器只返回受限栅格页，不向浏览器交付可执行 PDF；CLI 使用规范文本与来源元数据。
4. 清除覆盖原文件、报告、正文和既有索引；不新增持久缩略图缓存。公开格式能力、
   资源默认值、留存/导出合同、OpenAPI 与使用说明。

## 验收标准

- 真实中英文多页 PDF 经上传、解析报告、预览、确认发布；同名更新仍需正式身份决定。
- 页顺序、重复页、混合文本/扫描页和缺口可核对；部分结果未明确选择不能发布或自动采纳。
- 页码和片段由服务端从原文及固定版本解析，伪造页码/正文不能改变引用。
- 加密、损坏、超体积/页数、解压和超时被明确拒绝；脚本与链接没有执行或网络能力。
- 历史版本引用、页视图和规范文本一致；撤销访问和清除后旧引用不能恢复原文。
- 无资料学习及旧 Markdown 导入兼容；CLI 文本回退及未知原文件查看限制明确。
- 运行相关 Go/API/Web 测试、类型检查和构建，真实 PostgreSQL 发布/版本/清除测试，
  浏览器移动端/键盘测试及真实 PDF 页定位核对；未运行项逐项记录。

## 使用与能力合同

Web「知识与参考」先建立或选中集合，勾选有权保存 PDF 原件和提取文本，再选择
`.pdf` 文件。展开逐页报告核对；部分解析默认不选中，须单独勾选“仅纳入可用文本”。
之后沿用服务端预览、同名身份审阅和确认导入，最后自行选择用于哪个目标及参考角色。
上传、导入、采纳都不是教学完成或掌握度更新；不选参考仍能学习。

网页入口仍需明确外部读取授权；返回的原件、最终地址和服务端来源回执一并进入预览。
研究中混合页 PDF 不能自动采纳，手动采纳需 `accept_partial: true`。已有 #27 权限、
集合关联、冻结范围、父版本和确认回执继续生效，没有增加审批权限。

`GET /v1/knowledge/source-capabilities`（`knowledge:read`）返回具体支持范围。
`POST /v1/knowledge/reference-sources` 接受授权 URL 或 Base64 `pdf_data` 与
`storage_consent: true`，只返回解析候选；规范导入请求使用
`documents[].pdf = {data, accept_partial, locator?, source_receipt?}`，`markdown` 必须为空。
调用方不能提交提取报告、页码或代替原文的模型文本。OpenAPI 为权威字段定义。

| 资源 | 默认硬上限 |
| --- | --- |
| 上传原件 | 单份 4 MiB，单批请求仍受既有 12 MiB 限制（包含 Base64 开销） |
| 网页抓取 | 1 MiB 传输、2 MiB 解码；复用原 SSRF/DNS/逐跳授权限制 |
| 文件 | 100 个物理页；16,000 字节提取正文（不是字符数） |
| 执行 | 单任务最多 10 秒（含等待），全进程最多 2 个并发 |
| 解压/内存 | 每个 WASM 实例 128 MiB 线性内存；不映射宿主目录 |
| 页图 | PNG，最多 1000×1400 像素；不执行脚本、表单、嵌入链接 |

这里的内存值是 WASM 线性内存，不是整个 Go 进程 RSS；可信编译器缓存与受限
输入/输出缓冲另占宿主内存。解析器固定为 go-pdfium v1.20.0 / wazero v1.12.0，
每个文件独立实例；无原文件解压目录、宿主 Shell 或网络挂载。
服务在接收请求前通过 `pdfsource.Prepare` 编译可信 WASM，相关包测试也在准备阶段
执行同一步骤；冷编译只填充机器码缓存，不读取 PDF，不计入单文件的 10 秒预算。
文件任务仍从等待并发槽开始计时，实例初始化、解析和渲染均受原超时与取消约束。
超过正文预算保留明确的缺口；超页数/体积拒绝整份文件。密码文件不尝试破解。
压缩流耗尽内存即使由 PDFium 表现为无文本/页失败，也不能作为可用正文导入。

`complete_text` 只表示每页在当前预算内提取出了文本且未检测到额外缺口，
不表示阅读顺序、表格、公式或图片语义已验证。页码为物理序号，不是印刷页标签；
重复标记比较提取文本指纹，不删除原页，不宣称两页图像完全相同。
没有 OCR、手写识别、Office 或复杂图表理解能力。
未嵌入字体会标记 `font_not_embedded` 并要求明确接受部分结果：沙箱不访问系统字体，
页图可能使用替代字形或缺字。需要准确原页时应提供嵌入字体的 PDF，而非把提取成功
等同于字形显示成功。

## 保存、查看、导出与清除

- 用户上传须确认有权保存原件及派生文本；网页沿用禁止留存、登录、付费墙等检测，
  不因 PDF 格式绕过访问控制。系统不能自动判定所有版权许可，操作者仍须有合法授权。
- 正式原件、提取报告、逐页片段与 canonical Markdown 同事务写入不可变文档 payload；
  原文件 SHA-256 和解析器版本参与正文身份，原件变化产生新版本并走正式身份审阅。
  AI 综合保留独立 provenance，不更新原文提取。
- 来源预览不保存到数据库；Web 草稿在当前身份的内存中，未新建磁盘或浏览器持久缓存。
  未采纳网页 PDF 在既有加密研究运行正文中暂存，清除运行时删除；正式采用后由知识
  来源留存合同管理，清除运行不隐式删除已采用资料。
- 页接口 `/v1/knowledge/revisions/{revisionID}/documents/{documentID}/pages/{page}` 中
  `documentID` 是不可变文档版本 ID；执行知识读取权限、集合关联、冻结章节范围和隐私
  read permit 检查，只返回 `Cache-Control: no-store` PNG。不存在公共原件链接。
  页图只在请求期间生成；浏览器关闭视图或身份失效即释放临时 Blob。
- 导出仅提供已有的规范 Markdown/来源信息；不提供原 PDF 下载、原件打包或 CLI 图片查看。
  CLI 可正常 `library tree/preview/export` 读取派生文本及页码说明，帮助明确原页查看限制。
- 正规隐私清除覆盖原件、报告、提取正文、索引、运行加密附件和已有内容缓存；没有新增
  持久缩略图。历史引用清除后不再返回页图或正文；备份沿用既有备份销毁合同，而不是
  声称清除在线数据会立即擦除所有外部备份。
