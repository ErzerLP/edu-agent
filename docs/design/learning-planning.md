## 开发方案

结果：已有目标可选启动帮助完善，在独立交互页生成、编辑、审阅并明确采用结构化规划；模型不可用仍可保存和编辑草稿。

拆分评估：保留 #9 为一个主要用户流程，基础 owner 的缺口由各自前置任务交付。取得前置契约后，按以下三个垂直批次实施，每个批次包含生产持久化、应用服务、接口、页面及相关测试。不能先提交孤立 DTO 或 mock 作为功能交付。

### 第一批：手动草稿与审阅页面

草稿是独立可修订实体，保存稳定草稿 ID、草稿版本、学习区、目标 ID/版本、资料范围快照、适用教学上下文和隐私 generation。正式目标原文、用户自述、用户编辑与模型建议分字段保存和呈现。对话与表单均更新同一结构化草稿。

每个步骤包含用户可读名称、内容、理由、练习方向、完成依据、负荷、前置步骤及资料引用。引用使用 #3 的确定版本、文档/章节和服务端解析结果；名称由权威资料解析提供，模型不能伪造来源。允许无引用的大纲和缺口，但明确标记不可作为正式可评分路线。

提供独立 CLI/TUI 草稿列表、详情、来源查看、多行编辑、增删与重排。保存使用草稿版本和操作身份，冲突保留用户输入。清除、幂等回执和临时正文加入现有 learning 隐私门与残留检查。同步 OpenAPI、帮助和使用文档。

退出标准：无需模型即可创建、编辑和重启恢复草稿；这些动作不写正式目标、路线、会话或证据。跨区、失效引用和非法前置关系由服务端拒绝。

### 第二批：可选 AI 澄清与覆盖建议

输入合同：从服务端装配正式目标已填字段、用户尚未确认的草稿字段、已答澄清项、当前范围快照及有界检索结果、检索限制和适用教学状态。只询问缺少的必要信息，支持跳过与取消。已有回答不能仅因模型再次提问而丢失。

输出合同：严格结构化的澄清问题、建议目标字段、步骤、带引用的覆盖建议、缺口与不确定性。禁止输出 accepted Evidence、mastery、复习日期和业务状态；未知字段、非法结构、越界引用必须拒绝。资料覆盖描述与用户掌握程度分离，零命中只能表示本次检索未找到支持。

模型调用使用服务端既有配置与凭据，页面说明配置来源；不上传客户端模型 Key 或自动切换提供商。生成是独立有身份的操作，开始前保存已有草稿，失败或响应丢失后可查询真实结果。模型输出不能覆盖用户并发编辑，必须校验生成依据的草稿版本。

退出标准：成功、超时、非法结构、引用越界、取消和响应丢失均有可恢复结果；失败仍可打开已有草稿手动编辑，正式业务状态不变。

### 第三批：明确确认与正式应用

确认命令携带草稿 ID/版本、目标期望版本、范围快照及明确应用用途。服务端在同一权威事务边界重新读取并锁定相关版本、状态和引用，展示或返回过期差异；用户不能把旧草稿强行覆盖新事实。

由 #4 正式目标修订服务和 #5 路线应用服务执行选定变更。当前会话不适合修改时，按 #5 合同拒绝或允许用户选择新会话；不能自动切换用途。旧题目、作答、评估和证据保持原引用。不可靠大纲可以保留，但确认不能将其变成可直接出题评分的路线。

确认使用持久化 operation_id 和请求摘要，原子保存应用结果与回执。同请求重复点击、重试或响应丢失返回同一结果；不同请求复用同一身份明确冲突。取消已提交请求时查询真实回执，不能显示虚假的“未采用”。

退出标准：真实服务与模型 fixture 完成生成—编辑—确认—按所选目标开始学习；并发变更、重复请求及历史保留均有数据库证据。

公共 API 的最终路径、DTO 字段映射和数据库外键以所选 #3/#4/#5 契约为准；以上是消费要求，不是已发布接口。不能在前置尚未定型时维护第二套目标或资料范围真值。

## 2026-09-09 继续实施

用户确认前置已经推送后，将 `origin/main@7ef99f9` 合入 `task/19`，保留首次确认文档。资料范围、结构化目标、会话选择均使用已交付接口，没有创建第二套基础目标或资料实体。

公共合同位于 `server/api/openapi.yaml`：`GET /v1/learning/goals/{goalID}/plans` 列表，`GET /v1/learning/goals/{goalID}/plans/{planID}` 读取详情，向同一详情路径 POST `create/edit/generate/confirm`。每次写请求带 `operation_id` 与 `expected_version`；草稿 ID 由客户端先生成，失败时仍可按原 ID 查找。不同操作身份不能绕过草稿版本检查；同身份请求返回原回执，不重新调用模型或应用路线。

草稿保存原始目标修订、用户编辑的 `content`、独立模型 `suggestion`、有名称和准确范围/hash 的 `sources`。原文不被模型替换，自述不进入 Evidence 或 mastery。目标建议的字段与 #4 GoalDetails 同形，确认可只修订目标，也可仅应用路线，或明确同时修订目标。

模型通过已有服务端 TutorModel/llm adapter 调用，新增闭合 planning JSON schema；不使用客户端 Key。单次尝试最多 20 秒，沿用临时错误类别最多重试一次，用户取消停止后续尝试。外围保存事务最多 60 秒并独立于 HTTP 连接取消；模型失败保存可读错误和原草稿，已完成操作保存真实回执。模型期间持有草稿及目标锁，避免模型结果覆盖并发用户输入；这是有界同步流程，未引入后台 worker 或 Agent 框架。

资料只枚举用户冻结范围，模型上下文最多 100 个章节和 48KB 正文，页面明示限制。较大的章节可通过目标资料选择缩小范围；未命中或未枚举不证明资料不存在。无可靠引用的步骤可以保存和编辑，但不能作为正式路线应用。每次保存验证前置关系、重复节点、结构、负荷和引用；每次确认还锁定资料集合，重新检查目标修订、集合 head 与适用会话版本。集合出现新版本时要求重新冻结范围，新范围可以包含用户明确选择的资料。

正式确认使用原 learning 应用服务：外层数据库事务中的子操作使用保存点，目标修订、会话创建/转换、路线 proposal、路线应用和规划回执同事务提交。任何一步失败均回滚；回执响应丢失后重试不会重复创建。`current_session` 只用于 GoalReady、Diagnostic、RouteActive；正在出题或作答时可保留草稿并显式选择新会话。旧路线修订、题目、作答、评估和证据均保留。

## 使用与恢复

目标详情按 `p`，或使用：

```sh
edu-agent goal plan --id 目标ID
edu-agent goal plan --id 目标ID --plan 已保存草稿ID
edu-agent goal plan --id 目标ID --session 原教学会话ID
edu-agent goal plan --id 目标ID --plan 草稿ID --json
```

列表中 `n` 新建，可按名称/阶段选择关联会话，也可跳过。草稿页 `g` 可选 AI、`u` 将独立建议复制到可编辑草稿、`e` 填写或跳过澄清字段、`a/t/d/m` 增加/编辑/删除/重排步骤、`v` 查看文档章节正文、`f` 重新选择范围、`c` 预览后确认用途、`q` 返回并保留已保存内容。AI 不可用时直接使用手动编辑。确认后给出具体续学命令，并保存本进程的会话选择。仅确认目标时不创建会话。

失败时可用 `r` 重试同一请求；离开页面不表示服务端回滚，重新进入读取真实结果。草稿过期显示目标、资料或教学状态的差异类别，不能覆盖新事实；从最新目标创建新草稿再核对。旧诊断入口也必须明确确认后才应用路线。
