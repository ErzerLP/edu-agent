## 架构与责任

Go 服务在 `server/internal/app` 组装领域服务、PostgreSQL owner、HTTP 与 MCP。`learning` 保存事件、证据和投影，`tutoring` 负责会话状态机，`knowledge` 负责资料及版本，`learningspace` 提供显式范围。Go CLI 的 command 层通过 API 客户端查询，TUI 与客户端 Agent 复用读入口；管理 WebUI 有独立认证，不能借管理会话冒充学习设备身份。

本项只在前置 owner 提供的权威身份上增加聚合读模型与用户入口，不在客户端重建学习事实，不新增评分器、调度规则、目标 CRUD 或跨目标证据迁移。

## 开发前约定

以下为拟实施合同，尚非当前产品行为。字段映射需以接入后的 #3、#4、#5 正式契约为准。

- 范围采用显式区、目标和会话身份；目标所属区必须一致。全局读取是明确入口，不把省略范围解释为全局。继续学习和复习操作携带原任务身份，由正式执行路径再次校验。
- 路线进度以当前路线版本内权威完成步骤数除以有效步骤总数，同时返回分子、分母、版本与依据；无有效分母返回未知。有路线但没有完成事实时可以显示有依据的 0/N。
- 掌握状态展示已有 reducer 的状态、有效证据数、待确认数量及适用版本，不跨目标平均，也不新造掌握百分比。手动完成目标独立显示，不推导路线完成或已掌握。
- 历史事实保留原目标、路线、资料版本。当前范围失效或变化时说明适用关系；相关旧证据只引用真实来源，不复制 Evidence，也不自动归零或全部继承。
- 复习按 #5 的稳定真实任务身份去重，同一任务可出现在多个视图；同节点不同目标的独立任务必须保留。全局计数使用服务端去重后的任务集合，不能在分页后按节点合并。
- 默认总览展示进行中目标。暂停、手动完成和归档目标通过显式状态筛选查看，保留历史及队列；显示不可开始的原因，是否允许执行由 #4/#5 的正式状态规则决定。查询不改变截止日期、目标状态或复习到期时间。
- 默认排序使用已配置优先级、到期时间及稳定身份作为平局顺序，并返回排序依据；没有配置时明确标记，不创造优先级。用户可选择其他受支持排序。
- 服务端完成过滤、统计和分页。游标绑定规范化范围、状态、排序、截止时间及投影快照，跨范围游标拒绝；代次变化按既有 stale cursor 语义重新查询。
- 响应保留 as-of、提交高水位、投影代次、更新时间和 incomplete/reason 信息。成功空结果、查询错误、投影不可用、投影延迟和内容清除分别呈现。
- 活跃时间复用 `EstimateActiveTime` 的五分钟间隔上限并标明估算。事件按稳定事件身份只参与一次，不因资料关联或视图联接重复累加；不声称精确在线时长。

## 实施批次与退出标准

1. 接齐依赖并形成目标级查询闭环：核对资料范围版本、目标生命周期和复习任务身份，追加必要投影迁移，提供目标状态、路线、记录、活动、待确认、复习及继续位置查询。HTTP 与 CLI 至少能读取同一区两个目标的独立状态。退出标准为两区三目标真实 PostgreSQL 场景及目标版本变更用例通过。
2. 全局待办与复习闭环：在同一读服务实现范围、状态、排序与分页，通过正式任务执行路径开始复习。退出标准为稳定身份去重、不同任务保留、分页无遗漏、切换页面后作答归属不变，且队列及 Evidence 未因查询发生写入。
3. 独立页面与入口一致：交付可独立使用的 CLI 查询及进度/待办/复习交互页面，页面不依赖 #8；HTTP、MCP、Agent 与 TUI 复用同一范围和计数合同。更新 OpenAPI、CLI 帮助与用户说明，退出标准为跨入口结果一致和全部异常呈现通过。

保持一个需求、按垂直结果分批：每批包括生产查询和使用入口，不能以仅有 schema、DTO 或 mock 测试作为完成。具体 SQL、缓存和前置资源字段在依赖确认后再定，不先建立第二套任务或证据身份。
