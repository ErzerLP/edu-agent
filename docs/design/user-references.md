## 开发方案

一个主要结果是将可选参考从真实浏览器输入变为可核对的正式资料和后续教学上下文。
按三个有界批次实施，共享协议、隐私和组合根串行修改，不另建导入任务服务。

1. 新增明确授权的 references 配对档案，保留旧档案权限。知识页复用集合管理、共享、
   关联/解除、树、冻结与导出。文件选择只读取 File 对象，UTF-8 严格解码；粘贴、网页
   链接有逐项解析报告，网页复用 research.Fetcher 的网络边界。草稿仅保留于当前浏览器
   会话内存。预览与确认复用 operation、父版本、签名、身份决定和 lineage。
2. knowledge 保存目标或本次教学会话的不可变参考角色/范围及新上下文。通过
   learningchange 的权限、版本与具体差异审阅确认采用，审批绑定输入、目标、原政策、
   隐私代次和设备。限制只影响所选目标/现场；优先依据影响候选排序。后续导师准备使用
   新 context 并沿用原教学变更安全接入；已发行题目、答案与引用保持原版本。
3. 导师只能申请打开选择/审阅入口及读取已采用参考，不能调用导入确认、身份覆盖、
   共享、删除或 NoteSync。同步 OpenAPI、Web 校验、隐私清除与使用说明。

## 验收标准

- Markdown、UTF-8 文本、粘贴和网页实际内容完成解析、预览、确认、读取；不将路径当上传。
- 混合批次逐项区分成功、错误、不支持、排除；返回修改与请求失败保留输入。
- 服务端预览零发布；身份审阅支持更新、新建、跳过，不按文件名继承。
- 输入、集合、目标、父版本或身份选择改变后旧批准失效；未知结果核对原 operation。
- 集合增改、共享、发现、关联、解除和章节选择通过真实服务，不需要手工 UUID。
- 三种角色改变后续上下文/检索，目标和本次会话隔离，限制调整展示具体旧值/新值。
- 未采用资料不进入模型；模型只能请求用户入口，不能绕过批准或扩大权限。
- 不上传仍可正常保存目标和按原合同开学；导入和采用均不创建新目标或重置课堂。
- 已发行题目、答案、原引用和历史冻结范围不变；清除删除新增政策、回执与正文缓存。
- Web 类型、单测、构建、键盘/移动端浏览器场景及真实 PG 并发/事务/旧协议回归通过。
  缺少依赖或真实提供商授权的检查单列未运行，不冒充通过。
