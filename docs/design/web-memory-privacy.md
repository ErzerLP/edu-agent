# Web 长期记忆与数据隐私管理

## 问题确认与架构

#34 在本工作树确实缺失：基线 `clients/web/src/main.tsx:221` 的路由注册没有
记忆、数据或设备页面；`server/internal/identity/web.go:29` 的 WebScopes 过滤掉
memory/privacy/devices；`server/internal/mentorrun/core.go:48` 的正式工具表没有
记忆工具。现有管理页只读 Nocturne 树、CLI 本地历史不能替代此用户结果。

Go/PostgreSQL 的 memory owner 已负责候选、决定、版本、审计与交付；Nocturne
只保存准入后的正文。privacy owner 已编排各 owner 清除及逐存储回执。Web
使用同源 Cookie/CSRF，导师使用 agentcore、加密 checkpoint 和持久操作回执。
本项接通这些边界，不建立第二份记忆、成绩册或隐私清除实现。

## 开发方案

同一任务顺序交付三个批次，共享身份、OpenAPI 和导师协议，保持串行修改。

1. 记忆页面：候选/已保存/纠正/交付状态、详情、显式批准/拒绝、删除和有范围的
   导出。原服务增加可选强制审阅策略，Web 创建与纠正始终先产生候选；原 CLI
   自动准入合同不变。版本与 operation ID 绑定具体内容，冲突后重新审阅。
2. 导师闭环：受限工具只创建模型候选并暂停，用户在正式记忆面板审批；继续时
   查询真实候选/记录/交付状态，不以普通回复代替批准。候选写入和运行 checkpoint
   共用事务及实时权限检查。模型上下文只使用获准的全局长期偏好和原区正式学习
   事实，显示来源/范围；不持久复制 Nocturne 正文到工具历史。
3. 数据与设备：具体说明各删除动作边界；原一次性本机 grant 发起隐私清除，
   按真实回执显示失败、等待与外部限制。撤销复用设备服务，普通学习身份不获得
   管理面权限。显式 `memory` 配对档案承载记忆管理与设备撤销，不回填旧 token。

危险动作采用已有取消优先的确认对话框；错误只显示固定提示与请求 ID，敏感输入
不写入 URL/storage/log。正文只驻留当前身份内存，身份或隐私代次失效时清空。
隐私回执链接可携带无正文 ID，清除使原会话失效后重新配对查询。

## 验收标准

- 真实 PG 与 Cookie/CSRF：创建候选不生成记录，明确批准才交付；拒绝、取消、
  过期和陈旧版本不创建记录；同操作重试返回同一身份。
- 导师普通回复、临时时间限制不保存；记忆工具等待具体审批，继续取得真实回执；
  模型不能调用批准/删除/导出/清除工具；撤销权限即时阻止新写。
- 已保存详情、纠正、删除、导出、交付重放消费原服务；远端故障显示 queued/degraded，
  不宣称已保存或永久删除。全局范围、来源和学习事实权威边界可见。
- 隐私清除必须有效 grant；显示逐 owner 与远端失败，旧运行、历史、checkpoint、
  引用清除后无法读取或重新发给模型。已有各 owner 的集成回归一并验证。
- 设备列表、当前会话、取消优先的二次确认、撤销后新请求与活动订阅失效；
  普通身份没有 admin/配对管理权限。
- 桌面/移动浏览器完成候选审批和回执查询；导出限定长期记忆且无模型/搜索 Key。
- 运行相关 Go 测试、真实 PostgreSQL 集成、确定性远端 fixture、Web 类型/测试/构建
  和浏览器流程；真实 Nocturne 远端验收另列，未运行不算通过。

完成时同步 OpenAPI、部署白名单、权限/保存/删除使用说明和验收记录。工作仅提交
当前任务分支，不合并、变基或推送基线分支，由用户审阅落地。

以上为开发阶段边界；用户后续接受交付并明确授权本地 squash 落到 `main`，
实际落地按该新授权执行，未执行的验收仍保持未通过状态。
