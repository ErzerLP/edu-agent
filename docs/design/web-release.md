# 在线学习候选验收（Issue #37）

## 确认与架构

核查基线 `b0ddfac`，初始工作树干净。Go app 组合身份、学习、知识、教学、持久运行、
记忆和隐私 owner，PostgreSQL 保存权威状态；React 消费同源 HTTP，生产 Go embed
静态资产，CLI 使用同一学习协议。模型、搜索及 NoteSync 是独立外部依赖。
本项只补集成缺陷与验收入口，不新增业务状态机、数据库表或模型能力。

已确认的缺口：

- `clients/web/playwright.config.ts:3–20` 没有浏览器 projects；默认只跑 Chromium。
- `Makefile:120` 的 `check` 只接 Go 测试、race、vet 和构建，没有 Web 测试或发布验收。
- `clients/web/tests/browser/workspace.spec.ts:32–96` 的课堂夹具先导入资料，不能证明空库开学。
- `server/internal/transport/httpapi/web.go:269` 的 SPA 页面白名单漏掉进度、记忆和
  数据/设备页；`clients/web/src/main.tsx` 已注册这些页面，直接打开或刷新却返回 404。
- `deploy/web/nginx.conf:37` 漏放进度/复习、单批导入、参考来源、冻结范围和 PDF 页码 API；
  直连 Go 的浏览器测试发现不了生产反向代理的 404。

A01–A36 定义取自 [#40 总览](https://github.com/ErzerLP/edu-agent/issues/40)，
不借用历史 Comet 中恰好同号的验收项。#18–#36 的历史记录只用于定位已有覆盖，
未绑定当前输入、环境和实际日志时不视为当前候选通过。

## 开发方案

1. 为真实页面直达/刷新和 Web 消费的代理 API 建立先失败的契约回归，修正两处白名单。
   保留 API/admin/internal/静态资源错误边界，禁止扩大为全 API 转发或任意 SPA 回退。
2. 保留默认 Chromium 的快速开发入口；显式发布配置启用 Chromium、Firefox、WebKit，
   单 worker 串行运行真实 Go/PG 夹具。四视口、主题、IME、焦点和长内容复用现有测试。
3. 增加分层检查入口：无需数据库的 Web/Go/生成一致性/发行检查，以及需要显式测试库、
   真实浏览器与 CLI 的候选检查。依赖缺失、没有测试、测试跳过均不能生成通过证据。
4. 记录在线矩阵、A01–A36、八步核心脚本及外部/人工验收清单。fixture、真实提供商、
   原生设备与代理部署分别记账；候选未全部通过时明确阻止发布声明。

范围是一个发布验收结果；昂贵矩阵在局部回归通过后串行执行。外部提供商费用、部署、
推送与合并不由测试入口隐式触发。本次专用 worktree 的明确约束优先：提交任务分支供审查，
不合并、rebase 或推送基础分支。

## 验收标准

- 所有前端注册页面可直接请求；未知 API、管理/内部路径与缺失资源不返回 SPA。
- 前端使用的正式 API 均在代理允许范围；未交付/管理/内部接口仍拒绝。
- 三浏览器配置可独立选择，Chromium 专用路径不污染 Firefox/WebKit。
- 检查失败、缺依赖或 skip 的退出码非零；OpenAPI 漂移不能静默覆盖生成文件。
- 发行必须包含前端资产；缺资产的独立临时构建失败，不移走工作区资产。
- 当前候选实际命令、结果、环境和限制可追溯；每个 A 编号都有 owner、生产入口、
  证据入口和明确结论；未运行部分不标通过。
- 核心空库研究、真实提供商样本、代理 SSE、原生输入法/软键盘/读屏、性能和升级备份
  有独立待验收项；缺少这些证据时不能宣称 #37 全部验收通过或上线。
