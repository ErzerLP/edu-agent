## 三类教学样本

三类均执行：先保存目标 → 建立独立资料集合 → 正式导入两份自编 Markdown →
冻结范围 → 将范围绑定到目标修订 2 → 创建教学会话 → `start_diagnostic` →
正式检索 → 请求真实 `route` 提案。每个目标只发起一次路线请求，数据库
`tutoring_proposal_requests.attempt_categories` 均为 `{incompatible}`，没有自动重试。

延迟口径是客户端从发出正式提案 API 请求至收齐响应的时间，包含 HTTP、数据库和
校验开销；每类只有一次实际模型尝试，所以 p50 与最大值相同。这不是长期性能统计。
服务端教学响应没有暴露实际 Token 或金额，不能将失败请求算作零费用。

| 类别 | 资料原始字符数¹ | 实际模型尝试 | 提案 API p50 / 最大值 | 结果 | 实际 Token / 费用 |
| --- | ---: | ---: | ---: | --- | --- |
| 概念／推导 | 197 + 74 | 1 | 898 / 898 ms | HTTP 422 `proposal_rejected`，`incompatible` | 未提供 / 未核实 |
| 代码／算法 | 402 + 144 | 1 | 834 / 834 ms | HTTP 422 `proposal_rejected`，`incompatible` | 未提供 / 未核实 |
| 长文阅读 | 1342 + 120 | 1 | 871 / 871 ms | HTTP 422 `proposal_rejected`，`incompatible` | 未提供 / 未核实 |

¹ 临时脚本按 JavaScript 字符串长度统计，包含标题、空白及代码；正式导出由解析器添加
节点标记，长度更大。长文是一次约 1.3k 字符的多段阅读材料，不代表超长文档压力测试。

### 概念／推导：前 n 个正奇数之和

目标：推导前 n 个正奇数之和为 n²，用正方形增加一圈说明归纳步骤。
资料：`odd-square.md` 与 `odd-examples.md`，包含起点、归纳步骤及 n=3、4 的例子。
检索与冻结导出抽查到自编原文：“增加一行 n 个点、一列 n 个点和角点 1 个，共 2n+1 个点”。

会话 `456ea926-5e6c-4231-9a44-a4f0f2d30ccb`；路线请求
`670eb426-2442-49e9-8fdd-a15a7abd9632`。生成路线在 **898 ms** 后失败，费用未核实。
预定答案包含归纳起点及 `n²+2n+1=(n+1)²`，预定调整请求是改成点阵解释；由于没有
课堂，答案和调整均未提交。不存在可审查的模型教学引用、评估或调整输出。
最终读取确认目标正文、目标修订 ID、冻结范围未变；没有原题可验证。

## 真实提供商 smoke

### 服务端模型能力探测：失败

生产 Chromium 使用 `settings` 配对，通过正式
`POST /v1/settings/probes`，提交当前配置修订、`target=teaching` 和费用同意。
公开响应 HTTP 200，但业务状态为 `probe_failed`／`invalid_response`：
`structured_json=false`、`native_schema=false`、`requests=2`、`cost_estimate=unknown`。
端到端 **2685 ms**。不能将接口返回 200 算作能力通过。

为确认原因，另做三次直接、固定公开样本的诊断，均保持同一端点和模型：

| 诊断请求 | HTTP / 最终结果 | 延迟 | 上游报告 Token |
| --- | --- | ---: | --- |
| 原生 `json_schema`，64 输出上限 | 400，`This response_format type is unavailable now` | 779 ms | 未返回 usage |
| `json_object`，1024 输出上限 | 200，返回 `status/profile` 对象，缺少要求的 `capability_probe` | 2537 ms | 输入 76、输出 310、合计 386；其中推理 300 |
| 产品探测同款 `json_object`，64 输出上限 | 200，`finish_reason=length`，最终正文为空 | 1647 ms | 输入 76、输出 64、合计 140；输出全部为推理 |

三次诊断延迟 p50 **1647 ms**、最大 **2537 ms**；两个成功 HTTP 响应共报告 **526 Token**，
不覆盖整轮调用用量。金额均未提供、未核实。1024-token 诊断没有取得合格的探测
Schema；64-token 诊断直接确认最终正文为空，不将隐藏推理视作有效 JSON。

### Web 导师一次真实对话：通过

这是一轮普通聊天，未带正式资料引用，不计作课堂教学或引用质量验收。

运行 `e57ec6ff-fe19-4767-b4c8-1a9f1373cf03` 为 `succeeded`；从受理记录到完成记录
**2366 ms**（包含 worker 调度；单次 p50／最大值均为 2366 ms）。`requests_used=1`，

这次脚本等待失败不计作产品对话失败，也未增加调用数。

## 问题、处理与调用计数

1. **教学与提供商的原生 Schema 兼容性阻断。** 最小复现是配置指定端点／模型，
   保存目标并导入资料、建立诊断会话，然后正式请求 `route`；三个不同目标同样
   HTTP 422，数据库原因均为 `incompatible`。独立公开样本确认上游 HTTP 400。
   `server/internal/integrations/tutormodel/adapter.go` 固定请求原生 Schema。
   为此增加教学 JSON 回退并确保 Schema 进入模型上下文，需要专门兼容方案；本轮
   没有修改提示词、评分逻辑或生产代码，也没有绕过校验写入课堂状态。
2. **固定 64-token 能力探测与当前模型推理输出不兼容。** 回退诊断将 64 个输出
   Token 全部用于推理，正文为空。提高输出上限的独立诊断仍未遵守业务 Schema，
   所以不据此修改产品探测预算或标记能力就绪。
3. **CLI 凭据环境不具备。** 已如实记录正式 Agent 失败与零请求，未以明文 Key 兜底。
4. 三个目标的最终正文、修订和范围均受保护；这只覆盖失败生成与一次普通导师交流，
   不覆盖正在作答时的原题／草稿保护、针对性调整或评估质量。
