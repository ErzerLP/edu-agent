# Issue #64 开发方案与验收

## 架构与问题确认

基线 `dc03439`，任务分支 `task/87`。相较报告基线 `364fbe1`，只有验收文档变化。
项目由 React Web、Go 服务、PostgreSQL、Go CLI 和共享 agentcore 组成。
本问题涉及 Web 课堂正文异步恢复、learning 评估命令和 tutoring 会话状态；
客观题按原活动规则评估，不需要模型调用，不涉及评分政策或数据库迁移。

原始证据中，失败会话停留 `Evaluating`、版本 11，事件和操作回执止于提交答案，
没有评估事件或后续被拒绝的操作。页面既没有反馈，也没有提交结果提示。
当前代码的原始 Firefox 场景在本任务独立空库通过，与 issue 的定向复测一致。

随后在未修改产品代码时，以诊断用例控制真实正文响应：返回原教学会话后，
按下反馈按钮，释放正文响应，待正文显示再于原坐标松开鼠标。Firefox 实测：

- 按钮顶部由 `338.25px` 移至 `601.37px`，高度仍为 `44px`。
- `record_assessment` 请求数为 0，服务端仍为 `Evaluating`。
- 原 5 秒断言失败：找不到包含“已接纳”的“教学反馈”区域。

实施前代码定位：`teaching-page.tsx:327–359` 异步读取正文；`:714–715` 在读取完成前
显示原题回退；正文完成后插入版本链接、交互和来源块，改变后续控件的位置。
`:890–899` 的反馈按钮只检查写权限与操作忙碌状态，正文恢复期间已经启用。
`workspace.spec.ts:415–417` 返回课堂后立即点击，可能正好遇到此布局变化。
这证实当前代码存在同类点击竞态，不要求脏数据库；原矩阵没有点击跟踪，不能
断言其唯一诱因或把全部状态相关失败归因于此，也没有证据表明反馈永久丢失。

## 开发方案与验收标准（实施前）

单一小批次，仅处理课堂恢复时反馈入口的就绪状态：

1. 正文能力尚未确定或受支持的正文请求尚未完成时，暂时禁用反馈按钮；
   显示正文加载状态。正文不可用、不支持或加载失败后保留原题回退和反馈能力。
2. 在原评估场景中控制返回课堂的正文响应，断言加载时不可提交、完成后一次点击
   只产生一次评估请求；保留原版本、权限隔离、丢响应历史作废等全部后续断言。
3. 补充正文不可用、正文请求失败时的反馈回归，避免将可选正文服务变成评估依赖。
4. 先验证回归在原实现失败，再验证修复；串行运行 Firefox、Chromium、WebKit 的
   相关评估场景，以及 Web 类型检查、单测、生产资产和 Go 发行服务构建。
   不扩大为全仓检查；浏览器矩阵的其他已登记问题如实单列。

不增加超时或自动重试，不改评分、权限、幂等、历史记录和隐私语义。
仅提交任务分支供审查，不合并或推送基础分支。
