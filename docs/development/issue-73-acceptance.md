## 架构与问题确认

基线 `2ca85f5`，初始工作树干净。项目由 Go 服务、PostgreSQL、同源
React/TypeScript Web、独立 Go CLI 和共享 agentcore 组成。
learningcontent 保存正文修订及设备阅读偏好；mentorrun 负责选段模型运行；
learning/tutoring 保存原教学活动与答案。Web 使用 React Query 读取内容和偏好，
Playwright 通过真实服务、独立数据库 schema 和本地模型夹具验收。

以下行号对应修复前代码，足以确认报告中的竞态仍然存在：

- `clients/web/tests/browser/workspace.spec.ts:1072–1073` 从原运行返回第 2 版，
  只等待 URL 更新，没有等待内容或偏好加载。
- 同文件 `:1081–1085` 暂停匹配的所有偏好 GET。如果页面初始 GET 尚未发出，
  也会被这个本应覆盖后续刷新的拦截器挂起。
- `clients/web/src/teaching-page.tsx:1119–1130` 查询偏好，且 `gcTime: 0`，
  离开内容页后不能依赖旧缓存；`:1139–1140` 只有偏好存在才启用正文查询。
- 同文件 `:1188` 在正文不存在时仅显示“正在读取内容版本…”，因此不会渲染
  `:1228` 的 ContentTools；测试在 `workspace.spec.ts:1088` 等待收藏按钮超时。
- 暂停请求直到测试的 `finally`（`:1097–1099`）才释放，因此按钮自动等待或
  增加超时都无法打破这个等待关系。

这是验收前置条件的时序问题。初始读取与网络拦截谁先发生，解释了单例可通过、
完整文件偶发失败的现象；不据此认定正常网络下收藏或正文读取的产品逻辑有错。

从原运行返回后，先断言“收藏内容”按钮已可用，确保初始偏好和正文已加载，
再安装暂停后续偏好 GET 的拦截器。保留原超时、两个连续 PUT 的完整载荷断言、
收藏/固定回显以及请求释放清理。
